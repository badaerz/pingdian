## 三个独立缺陷（按修复顺序）

### 1. Prompt 从未声明字段形状 → 5/6 失败

模型返回的 `analysis` 是字符串或对象（应为 `AnalysisDimension[]`），`diagnostics` 是对象（应为数组）。

`taskInstructions["analysis-v2"]` 只写了一串字段名，没有给出任一项的**结构**。模型于是自由发挥。

修复方向：把形状规格写进 instruction。已在 `scripts/diagnose-validation.mjs --with-shape-spec` 中验证有效——加上形状规格后，形状类失败归零。

### 2. `taskMaxTokens["analysis-v2"] = 5000` 不够 → 补形状后 4/4 被截断

`finish_reason: "length"`。完整 payload（含 6 项 style metric、图谱、双曲线、热力图、domainAnalysis）在 5000 tokens 内写不完，JSON 被切断。

修复方向：提高到 9000+（实测 9000 可通过），或拆分任务。**注意**：提高 token 上限会增加成本，需与"单次分析成本"一起记账。

### 3. `validation.ts:341` 强制叙事类必须有一条"铺垫不足" → 4/4 失败

```ts
if (value.sourceKind === "narrative" && !diagnostics.some((item) => /(铺垫.*不足|不足.*铺垫)/.test(...))) return null;
```

这是**为了黄金演示路径那一个点击点，在最底层硬编码了一条内容要求**。后果：

- 任何不含"铺垫不足"的正确分析被整包丢弃；
- 反例样本（GC_013，健康文本）**在结构上不可能通过**——它本来就不该被判有铺垫缺陷；
- 模型被逼着必须造出一条"铺垫不足"，直接推高幻觉率。

这一条与 v2.0 的核心卖点直接冲突，是**必须删除**的，不是调整。演示需要那一条诊断时，应由 prompt 引导 + 证据校验保证，而不是靠校验器强制内容。

## 第四个问题（比前三个更严重）

修复前三个之后，模型确实通过了形状校验，但诊断内容质量不可接受。抽样：

> GC_001：`'将到了'与'到了'重复，影响流畅度` / `'育养'一词稍显生硬` / `'一副'用于笑脸稍显不搭`
> GC_004：`'翻翻覆覆'略显生硬` / `'正是'一词稍显直白` / `'耸'字稍显文言`

**这是校对意见，不是文学诊断。** 全部停留在字词层面，没有一条触及：
伏笔、视角、结构、意象、节奏、人物弧光——即 golden set 真正标注的 44 条应得结论。

对照 GC_003 的输出（`外貌降级的顶点，长衫换破夹袄`、`矛盾修饰收束，留白使死亡成为社会性事实`）——
**同一条 prompt，同一模型，能力是有的，但不稳定**。GC_003 抓到了，GC_001 和 GC_004 掉进了校对模式。

这说明真正的问题不是模型不会，而是 **prompt 没有把"诊断维度"约束住**。
当前的 instruction 只说了"返回什么字段"，没说"判断必须落在哪些维度上"。

## 对 v2.0 路线的修正

v2.0 §3.1 认为瓶颈是"专用知识库"。基线数据支持一半、修正一半：

- **知识库确实不够**：现有 20 条按**作品**组织（KB_001 孔乙己的技法说明），不是按**评价维度**组织。检索召回的是"边城的意象运用"，不是"铺垫不足的判定标准"。所以模型即使想引用"法条"，也没有法条可引。
- **但更近的瓶颈是 prompt 与校验器**：这两个改起来是小时级，知识库重构是周级。先改近的。

**结论：在重建知识库之前，先做"维度约束 + 逐条丢弃"。**

## 不可混淆的口径

本次记录的 0% 不是"模型能力分数"，是"链路可用性分数"。
对外只能说："我们建立了评测体系，首轮基线暴露了诊断链路 100% 失败，据此定位出三个结构性缺陷。"
不能说："我们的模型准确率是 0%。"——这两句话的含义完全不同，前者是 AIPM 的方法论，后者是产品事故。
