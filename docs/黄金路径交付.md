# 黄金演示路径与判据判定过程

## 修改前审计

下表记录改动前的代码路径与测试可证明的范围。浏览器复测、各任务的入口另见同目录两份审计表。

|步|实际路径|初判|证据|
|---|---|---|---|
|1|首页「查看答辩案例」进入本地项目|真实（本地操作）|core-flow 的 primary case link 用例|
|2|候选需要与上下文版本一致才自动发起检查；旧版本候选需要重新检查|降级但可见（无密钥）|CandidatePanel 的 autoCheckKey、consistencyReport|
|3|内置快照可看图表；重跑会请求服务器。等待时按计时器显示检索、校验及百分比|不真实（进度）|AnalysisWorkspace、AiProgress 的 stageFor|
|4|带原文证据的诊断可点击打开证据抽屉|降级但可见（案例来源）|analysis-flow 与 EvidenceDrawer|
|5|四段面板展示结论与判据；尚无本例判定记录|降级但可见|analysis-explain-panel.test.tsx|
|6|专项训练可由诊断进入；请求中修改答案会使旧响应无法解除 loading|不真实（卡住）|TrainingWorkspace 的 answerRevisionRef、submit|
|7|上传临时作文可以生成图谱；结果标注来源，慢请求没有用户可操作的取消按钮|不真实（慢请求）|KnowledgeWorkspace 的 requestRef、AiProgress|
|8|既有用例分段测试，未记录同一次完整 live 路径耗时|不真实（尚无完整 live 计时证据）|core-flow.spec.ts|

22 项注册任务中，旧版 analysis、training 仅保留 API，其余入口见《黄金路径任务入口》。已有可取消请求使用的 AbortController 多在组件卸载或切换时触发，等待中的用户缺少取消操作。新建向导切换步骤后仍可能收到上一步的候选。

## 改动后

|改动前|改动后|验收证据|
|---|---|---|
|内置案例无法改设定|复制后编辑副本，提示按新设定检查候选|studio-editing 组件测试、八步浏览器复测|
|分镜和一致性报告未独立显示来源，向导并行响应可能覆盖演示说明|分别显示当前分镜、报告及人物与世界候选的来源|ip-lab-flow、candidate-recovery-consistency、new-project-wizard|
|计时器模拟了后台阶段；没有超时取消入口|12 处模型请求使用共享传输。超过 3 秒展示请求名、等待状态、独立取消操作；取消会传播至上游模型请求|slow-ai-requests、ai-user-key；两项组件用例覆盖并发取消和等待响应正文时取消|
|训练提交期间编辑可卡死，向导会接收上一步响应|修改答案恢复提交，切步骤后旧响应作废|training-flow、new-project-wizard|
|图表缺字段时没有下一步|缺关系、节奏、情绪、热力或风格数据的页签显示原因并指向重跑|analysis-flow|
|知识图谱忽略当前请求的取消错误|取消后原文仍在，分析按钮恢复可用；回退原因直接显示|knowledge-academic-flow|
|在线诊断未返回适用练习时没有后续入口|明确提示未关联练习，并提供训练目录|analysis-flow 的 exercise directory 用例|

复测记录见 [黄金路径八步审计](黄金路径八步审计.md)，逐任务入口见 [22 项任务入口](黄金路径任务入口.md)。旧版 API 入口保留供兼容。校验段只有实际丢弃条目时显示具体原因。

## 判定过程

`criteriaEvaluation` 是可选字段。校验器验证判据编号及原文证据引用，逐条排除无效判定记录。判据规则来自本地库，计数说明和达标判断来自响应，面板并列展示原文证据供复核。没有有效记录的诊断显示「本次未提供判定过程」。相关单测覆盖缺字段、伪造判据、无效引用、存档恢复及面板展示。

## 回放门槛

当前工作区的 `evals/runs/` 缺少真实 raw 文件。完整 `npm run verify` 因当前协议、旧协议及归一化回放读到 0 份而失败。现有门槛保持生效，补回原始数据后可直接重跑。
