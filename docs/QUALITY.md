# QUALITY.md — 质量标准与验收口径

> 本文回答一个问题：**什么算"做完了"**。
> 任何 PR 说明里写"已完成"时，必须能指出对应的一行。

## 1. 强制门禁（必须全绿）

```bash
npm run verify
```

等价于：

| 门禁 | 命令 | 拦住什么 |
|---|---|---|
| 类型 | `npm run typecheck` | 接口改动未传播到所有调用点 |
| Lint | `npm run lint` | 未使用变量、hook 依赖错误、Next.js 规则 |
| 分层 | `npm run check:layering` | `lib`/`data` 反向依赖 `components`/`app` |
| 文件大小 | `npm run check:filesize` | 新文件超过 500 行 |
| 单测 | `npm test -- --run` | 逻辑回归 |
| 构建 | `npm run build` | 生产构建失败 |

**任何一项红，不得声明完成。** 唯一例外：`check:filesize` 对存量文件有豁免白名单（见 `scripts/check-filesize.mjs`），豁免只减不增。

## 2. 验收标准写法

**禁止**："支持文学诊断"、"页面能用"、"功能上线"。
**必须**写成可被机器或明确人工步骤检查的句子。

| 差写法 | 好写法 |
|---|---|
| 支持证据校验 | 一条诊断的 `evidenceIds` 若不含任何 `source: "observation"` 的证据，该条诊断被单独标记为 `discarded` 并附 `discardReason`，其余诊断正常返回 |
| 可解释面板 | 面板四段各自渲染非空区域；无数据段显示明确的空状态文案而非空白；被丢弃结论单独列出且含丢弃原因 |
| 演示不卡顿 | 黄金路径 3 分钟内走完，无超过 1.5 秒的白屏，无「加载中」停留超过 8 秒 |

## 3. AI 输出的五条硬纪律

这些是产品红线，任何改动都不得放宽：

1. **证据可核验**：`observation` 类证据的 `quote` 必须逐字出现在用户原文中；`knowledge` 类证据的 `quote` 必须出现在对应 `retrievalId` 的检索内容中。由 `validation.ts` 机器校验。
2. **不伪造来源**：客户端传入的 `retrievalEvidence` 一律丢弃，只用服务端检索结果。
3. **失败不写脏数据**：校验失败时不得把任何模型输出写入 `StoryState`。
4. **降级要诚实**：无法得到可用结果时，返回 `mode: "demo"` 的确定性回退并附 `warnings`，**不得**把回退结果伪装成 live。
5. **不代写**：`training-feedback-v2` 不得返回可直接提交的替代作文；`story-direction` 不得返回正文候选。由校验层强制。

## 4. 测试要求

- 新增 `lib` 纯函数：必须有单元测试，覆盖正常路径 + 至少一个边界。
- 新增 AI 任务：`ai-tasks.test.ts` 与 `ai-validation.test.ts` 双向补用例（能通过 / 必须拒绝）。
- 修复缺陷：**先写能复现失败的测试**，再改代码。
- 组件测试不要断言 CSS 类名，断言可访问语义（role / label / 文案）。

## 5. 文档要求

- 新增架构级决策 → 写 `docs/exec-plans/completed/` 下的计划文件，或在已有文件里补一节。
- 改变依赖方向或分层 → 同一 PR 内更新 `docs/ARCHITECTURE.md`。
- 改变验收口径 → 同一 PR 内更新本文件。
- **文档与代码不一致时，代码是对的，文档必须改。** 不允许"先这样，回头再补"。

## 6. 记录系统的边界（v2.0 起）

课程原话是"仓库即记录系统 —— 不在仓库里的东西，对智能体来说不存在"。本项目据此加一条：

**对话里达成的、会影响后续开发的决策，必须在同一天落到仓库文件里**，否则视为未决策。

落点：产品取舍 → `docs/product-specs/`；工程决策 → `docs/exec-plans/`；口径变化 → 本文件或 `ARCHITECTURE.md`。
