# 判据知识库（docs/knowledge）

这份目录放的是**文学诊断 Agent 的判定标准**——产品最硬的资产，也是「防幻觉」卖点的法条来源。

## 三份文件，各管什么

| 文件 | 给谁看 | 回答什么 |
|---|---|---|
| `判据知识库_v1.0.md` | 机器 + 人 | 18 条判据是什么、怎么算、什么情况下不适用 |
| `判据库维护手册_v1.0.md` | 人 | 标准怎么来的、怎么改、为什么某些东西不评 |
| `检索契约_v1.0.md` | 写代码的人 | 标准怎么进 prompt、怎么被引用、怎么被校验 |

## 一句话看懂这套判据的价值

**不在于它测得多全，而在于每一条都能说清「凭什么这么判」「判不了的时候承认判不了」。**

六维 × 3 条 = 18 条，覆盖：具体性与感官（P1–P3）、意象复现（M1–M3）、结构组织（S1–S3）、连贯衔接（C1–C3）、信息密度与节奏（D1–D3）、视角一致性（V1–V3）。

## 三条任何时候都不能破的纪律

1. **`C1`、`D2` 是 `draft-pending-threshold`**——阈值依赖尚未建立的参照带，只采集数值、不产出达标结论。**不许给它们补阈值。**
2. **判据 ID 必须可溯源**——诊断结果的每条结论都要引用判据编号（`P3`、`S2`…），引用了不存在的编号、或引用该文本不适用的判据，在代码层丢弃。
3. **校对类意见不是文学诊断**——「措辞生硬」「用词不当」这类必须挡在门外。判据是：**如果这条意见换成另一段文字也成立，它就不是针对这段文本的诊断。**

## 改判据之前

先读 `判据库维护手册_v1.0.md` §3.2 的改动分型表。**改 `statement` 是改承诺（要升 major），改 `metric` 是改实现（minor）**，两者后果差一个数量级。

版本号存在两处，必须同时改：文件名 / 文首标题，以及 `src/lib/ai/criteria.ts` 的版本常量（该文件尚未创建，见检索契约 §8）。

## 与其他文档的关系

- **`docs/QUALITY.md`**：工程质量标准。本目录管「判什么」，QUALITY 管「怎么保证代码可靠」。
- **`docs/product-specs/literary-diagnosis-agent.md`**：诊断 Agent 的产品规格。本目录是它的判定标准细化。
- **`docs/exec-plans/`**：执行计划。判据库的落地（注入 prompt、评测）见其中 Sprint 记录。
