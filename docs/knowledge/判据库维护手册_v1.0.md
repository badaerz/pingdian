## 0. 三种读者，三种读法

| 你是谁 | 你该读哪节 | 你要拿到的东西 |
|---|---|---|
| 三个月后的我 | §3 改动流程、§2 否决记录 | 别再重复已经否决过的方案；改一条判据要动哪些东西 |
| 协作者（产品 / 开发 / 评测） | 全文，重点 §1.1 §1.2 §3.2 | 为什么是这六个维度、判据怎么变、变了之后评测怎么跟着变 |
| 面试官 / 评委 | §1 由来、§2 否决记录、§4.4 答法 | 这套东西有没有方法论，边界在哪，出问题怎么兜 |

一句话立场：**这套判据的价值不在于它测得多全，而在于每一条都能说清「凭什么这么判」「判不了的时候承认判不了」。**

## 1. 这套判据是怎么来的

### 1.1 四条准入标准（缺一不可）

每条判据进来之前要同时过四关，少一关就不要：

| 标准 | 具体含义 | 反例（真实被卡掉的） |
|---|---|---|
| **有公认出处** | 能在公开、可打开、可核验的来源里找到对应表述，且不能把"省级转述"写成"课标原文" | 「反讽」——理论上有（新批评），但没有一条能落到可数的文本标记上 |
| **可量化** | 能写成「数出来的东西 = 几」的形式，两个标注者对着同一段文本能算出同一个数 | 「人物塑造是否立体」——"立体"没有计数口径 |
| **AI 可实现** | 现行模型在零样本下做得到，不是理论上可做 | 「全知视角判定」——实测零聚焦 F1 只有 36.16（*Says Who?* 2025），几乎等于抛硬币 |
| **符合产品定位** | 服务于「告诉你为什么这样写、哪里不好，且每条结论绑定原文证据」 | 「文采/优美度」——只能给印象分，给不出证据 |

四条标准的来源是我们自己的失败：前两轮方案（3 条叙事维度、12 个描述字段 + 规则引擎）都是因为**第 3、4 条不过关**被打回的——维度看着专业，模型判不准，产品也用不上。

### 1.2 为什么只做六个维度

六个维度不是从理论推出来的，是**两个公共体系求交集 + 一次覆盖检验**的结果：

- **6+1 Traits**（NWREL / Culham）：ideas、organization、voice、word choice、sentence fluency、conventions、presentation
- **高考作文评分标准**：基础等级（内容：符合题意 / 中心突出 / 内容充实 / 情感真挚；表达：符合文体 / 结构严谨 / 语言流畅）+ 发展等级 12 点

两个体系里同时存在、且能落到可数指标上的，收敛到六个：

| 维度 | 对应 6+1 | 对应高考评分 |
|---|---|---|
| 结构组织 | organization | 结构严谨 / 符合文体 |
| 连贯衔接 | organization（句段层） | 语言流畅 / 结构严谨 |
| 信息密度与节奏 | ideas（充实度）+ sentence fluency | 内容充实 / 语言流畅 |
| 具体性与感官 | word choice + ideas | 内容充实 / 情感真挚（"真挚"要看细节不看形容词） |
| 意象复现 | word choice + ideas（深层） | 中心突出（意象是主题的载体） |
| 视角一致性 | voice（可判定部分） | 符合文体（叙事文体的基本契约） |

**覆盖检验**：把现有 golden set 里 44 条 `expectedFindings`（原本散落成 23 个自由标签）逐条映射回六维，44 条全部有归属——视角 6 / 具体性 15 / 意象 11 / 结构 6 / 密度 3 / 连贯 3。这说明六维不是"砍到只剩六个"，而是原来那 23 个标签本来就在这六类里，只是没被收拢。

### 1.3 为什么不开第七维

最常被问的是「为什么不做人物塑造」。答案是它**过不了第 2 条标准**：人物塑造不满足"可量化"。

但这不是说人物塑造不评——它的成分被拆进三个已有维度：

- 「人物有没有被写活」→ 具体性与感官（有没有可指认的动作、物件、身体细节）
- 「人物有没有变化」→ 意象复现（同一物件在复现中变形，指向处境变化；如"长衫"到"破夹袄"）
- 「人物在结构里起什么作用」→ 结构组织（段落功能与转折）

拆完之后，"人物塑造"这个维度就没有独立内容了——它变成了另外三维的合成结论。合成结论不适合当判据（不可二值判定），但适合当**诊断报告的组织方式**。

### 1.4 返工记录（这是方法论的主体）

判据库不是一次写成的。18 条判据分四批产出，其中第一批与第二批各经历了一次返工，最后又做了一轮合并审改。**批次与轮次不是一回事，这里按批次记**——每一批暴露的都不是"模型理解错了"，而是**规则本身的缺陷**。这张表比判据本身更值钱：

| 批次 | 返回次数 | 暴露的缺陷 | 沉淀成的规则 |
|---|---|---|---|
| 第 1 批（P3 / M3 / S1） | 一次返工（`_v2`） | 判据的 metric 会把自己的反例判成达标；反例撞自己的误报清单；出处把省级转述标成课标 | **R1 穷举**（否定式必须穷举形态）、**R2 互斥**（反例不得是误报清单里的类型）、**R6 出处纪律**（source 写实际文件名，不许升级权威性） |
| 第 2 批（S2 / S3 / C1 / C2 / C3） | 一次返工 | ①「抒情评述」与「归不进去」互相吞并，空集恒成立；② 连接词清单过宽，把"都是学生"判成有衔接；③ 为修①加了一条"统一必要条件"，又把另一个判定形态排成空集 | ① 的修法沉淀为 **R1 的延伸**：口径必须给出**边界情形**，否则清单过宽/过窄；③ 的修法沉淀为 **R8 交叉引用自检**（出现「任何 / 全部 / 一律 / 皆 / 只有」，逐条回答"这条排除了什么？被排除的里面有没有本该保留的？"） |
| 第 3 批（D1 / D2 / D3 / P1 / P2 / M1 / M2 / V1 / V2 / V3，共 10 条） | 其中 4 条（V2 / D1 / D3 / P1）返工 | 60 字上限装不下跨段判据；阈值依赖不存在；V2 的视角人物判定法与被判定对象同一，构成循环论证 | **R3 字段冲突**（二选一必须明说）、**R7 阈值纪律**（未定就标 pending，只采集）、**判定依据必须与判定目标不同源** |
| 合并（v1.0） | 本轮 | ①「字」的口径四批没统一（汉字 vs 含标点）；② 第 1 批三条例目的 `notApplicable` 没给识别方式；③ **例句用 `/` 斜杠冒充分段**，与 metric 的「按换行切分」冲突，M2 正例按实现会判成"不适用" | ① 合并时统一为汉字口径并登记待补；② **R4**：`notApplicable` 必须可识别；③ 例句的分段方式必须与 metric 一致，**回代要按实现真跑一遍，不是读着像就算** |

**这张表真正的规律**：四批里有三批犯的是同一类错误——**改了 A，没检查 A 和 B 的交互**（第 2 批的①③、第 3 批的 V2 循环、合并时的③都是这个形状）。这就是 R8 存在的原因，也是为什么每批只做 5 条——批次一大，人工回代就算不动了。

**修法上的一个教训**：每次为堵一个洞而加"统一条件"，往往会造出另一个空集。所以 R8 必须连着 R1 一起用——**加限定词之前，先问它会把谁排除掉。**

## 2. 为什么某些东西"不评"

这一节比 §1 重要。**能说清不做什么，比说清做了什么更能证明方法**。

### 2.1 否决记录

| 被否决的 | 理由 | 现状 |
|---|---|---|
| **暗示与明写** | 属"文本意义表达方式"，与六维各自测的质量不是同一层的东西。硬塞进来会混淆"有没有说清"和"用什么方式说" | 永久否决 |
| **人物塑造（作为独立维度）** | 不满足"可量化"；成分拆入具体性、意象、结构三维（见 §1.3） | 永久否决为维度，保留为报告组织方式 |
| **校对类意见**（措辞生硬、用词不当、标点、错别字、方言） | 不是文学诊断。判据：**如果这条意见换成另一段文字也成立，它就不是针对这段文本的诊断** | 永久否决，且在产品层必须拦住 |
| **主题深度** | 需要读者立场与阐释框架，不可二值判定 | 永久否决 |
| **反讽** | 依赖语境与言外意图，标注者之间一致性过低 | 永久否决 |
| **幽默** | 主观且强文化依赖，无法建立稳定标注 | 永久否决 |
| **Voice / 原创性** | 不可复算，且与"防幻觉"直接冲突（模型会倾向于编造"这里很有个人风格"） | 永久否决 |
| **语法与标点** | 属校对，且已被证明会**挤占**诊断（见下） | 永久否决 |

**校对类为什么必须挡在门外，有一个实证**：在评测基线阶段，`analysis-v2` 在真实模型下通过校验后，输出的内容退化为校对意见——"育养一词稍显生硬""翻翻覆覆略显生硬"，而同 prompt 同模型在另一个样本上能输出"外貌降级的顶点，长衫换破夹袄"。也就是说，**不是模型不会做文学诊断，是它一旦被允许谈措辞就只会谈措辞**。这条实证是"排除校对类"最硬的依据，比任何理论都管用。

### 2.2 三条否决判据（可以复用的判断法）

以后再有人提新维度，用这三条筛：

1. **可替代性检验**：如果这条意见换成另一段文字也成立，它就不是针对这段文本的诊断 → 退回。
2. **可量化检验**：两个标注者对着同一段文本，能不能算出同一个数 → 算不出就退回。
3. **可实现检验**：现行模型零样本下的稳定性够不够（有过实测就拿实测，没有就做 20 条小样本试标）→ 不够就退回。

### 2.3 否决记录怎么用

被问"为什么不做 X"时，标准答法是三段：**先承认它在文学上成立 → 再说它过不了哪一条准入标准 → 最后说它的成分被怎么处理了**。

例如被问主题深度：

> 主题深度在文学批评里当然是核心问题，但它过不了"可量化"这一关——同一段文本，不同读者可以说出完全相反的主题判断，而且都有道理。我们的做法是把"主题"降维成可数的东西：意象有没有复现、复现时有没有变形（M1/M2/M3），因为主题在文本里通常是通过反复出现的具体物承载的。判不了主题本身，但判得了"承载主题的装置有没有被写出来"。

## 3. 改动流程

### 3.1 判据的生命周期

```
draft                →  draft-pending-threshold  →  agreed
（能二值判定，待复核）    （阈值未定，只采集）        （人工审定 + κ 达标）
```

- `draft`：规则自洽、例句可回代，但还没经过独立标注者复核。
- `draft-pending-threshold`：`C1`、`D2` 专用。**只采集数值，不输出达标/不达标**。不许自拟阈值——`assertsForbidden` 的 0.8 重叠率就是拍脑袋定的，后来被证明是"记分板上的假精确"。
- `agreed`：至少两名独立标注者对同一批样本判定一致（κ ≥ 0.6，Landis & Koch 的 substantial 线），且分歧点已记录。目前全库为 `draft`，没有任何一条是 `agreed`——这一点必须如实说。

### 3.2 改动分型表

改一条判据之前，先认出这是哪一型。**不同类型的后果差一个数量级。**

| 型 | 改什么 | 影响面 | 必做动作 | 重跑 golden set？ | 版本 |
|---|---|---|---|---|---|
| **A** | `statement` | 与 PRD 的对应关系、评测口径、对外表述 | 产品侧确认语义未变；同步 PRD 与评测文档；标注侧重标受影响样本 | **必须**（离线 + 有 key 时 live） | **major** |
| **B** | `metric` / `checkable` | 可复算性、回代结果、边界判定 | 每个 `typicalFalse` 代回算出数值写进 note；验收方手工复算；检查与相邻判据的交互（R8）；**同步改 `src/lib/ai/criteria.ts` 的版本常量**（见 §3.6） | **必须** | minor（若判定结果反转则 major） |
| **C** | `typicalTrue` / `typicalFalse` 例句 | 只影响示例，不影响判定 | 回代自检；保持正反例成对；不撞 `commonFalsePositive`（R2）；**分段方式必须与 metric 逐字对齐**（V6） | 不必 | 不改版本 |
| **D** | 新增一条判据 | 维度内的覆盖、与已有条目的分工 | 编号顺延；补 §2 判据列表；在 §4 分工表登记新的一对；跑 R8 | **必须** | minor |
| **E** | 建立阈值（`draft-pending-threshold` → `draft`） | C1 / D2 从"只采集"变成"可判定" | 参照带建好；阈值写进 metric；补正反例；重标样本 | **必须** | minor |

**A 与 B 的区别，一句话说清**：`statement` 是给人看的产品语言（"这条判据管什么"），`metric` 是给机器算的算法（"怎么算出来"）。改 statement 是改**承诺**，改 metric 是改**实现**。承诺变了要通知所有下游（PRD、评测、对外话术），实现变了只要保证算出来的结果还认得出原来的正反例。

**什么情况必须升 major**：

1. 任一 `statement` 的语义发生变化（哪怕只是加了限定词）
2. 六个维度增删，或维度改名
3. 条目编号重排（`id` 是引用锚点，重排等于断链）
4. 两条判据合并或拆分

### 3.3 验收清单（V1–V9，唯一的质量门）

新条目或改动的条目，必须逐项过：

| 项 | 检查 |
|---|---|
| V1 | 11 个字段齐全，JSON 可解析 |
| V2 | `statement` 与规格逐字一致（不得改写） |
| V3 | `checkable` 可二值判定；否定式已穷举形态（R1） |
| V4 | 正反例成对，长度符合 §1.1 分级 |
| V5 | 反例不撞 `commonFalsePositive`（R2） |
| V6 | **回代检查**：每个例句能按 metric 算出 note 里写的结果（验收方手工复算，这是核心项）。**分段、字数、词表口径必须与 metric 逐字对齐**——例句里不得用 `/` 之类的符号代替换行；凡 metric 要求「按换行切分」的，例句就必须真的分行。人眼读着"像两段"不算数，要按实现的方式切一遍 |
| V7 | 跨段判据已按 R3 明说呈现方式 |
| V8 | 出处可打开、标题相符；不得升级权威性（R6） |
| V9 | 无作品名 / 作者名 / 人物专名（R5） |

### 3.4 版本规则

- **v1.1（minor）**：补内容、修措辞、统一口径，不改承诺。目前已累积 3 项待办：P3/M3/S1 的 `notApplicable` 补识别方式、两个重复出处标签合并、S2/C2 各一条反例补足到 15 汉字以上。（M1/M2 例句补长与斜杠分段已在 v1.0 修订中完成，见 §1.4 合并行。）
- **v2.0（major）**：改承诺、改结构（见 §3.2 四条）。
- **每版必写**：改了什么、为什么改、谁批的、影响哪些已上线能力。

### 3.5 pending 条目的阈值怎么建（C1、D2 专用）

`draft-pending-threshold` 不是永久状态，但它解不开的原因很具体：**阈值要靠参照带标定，参照带要靠采集，而采集不能混在日常诊断里做。**

**做法**（见《检索契约》§3.6）：日常诊断**不注入** C1、D2；另跑一条离线采集，只要求模型报数值：

| 条目 | 采集什么 |
|---|---|
| `C1` | `P`（相邻句对数）、`K`（可命名关系句对数）、可命名率 `K÷P` |
| `D2` | 各段密度、`max`、`min`、`gap = max − min` |

**样本量**：同一形态（叙述类 / 议论类必须分开算）累积 **≥ 30 个**，取分位数定阈值。目前 golden set 14 条全是叙事类，离 30 还差 16 条。

**定下来之后走 E 型改动**：阈值写进 `metric` → 补正反例 → 重标样本 → `confidence` 从 `draft-pending-threshold` 改 `draft` → 版本升 minor。

**在那之前，纪律是硬的**：产品界面上一律不显示 C1、D2 的达标结论，只显示"本条判据的阈值仍在标定中"。校验层要拦死——pending 条目若返回 `pass`/`fail`，按 `pending_verdict_forbidden` 丢弃。

**为什么值得单开一节**：这是全库唯一一处"承认判不了"的地方，也是最容易被面试官追问的地方。答案必须是具体数字（30 个样本、取分位数），不能是"以后再说"。

### 3.6 版本号在两处，必须同时改

版本号存在于两个地方，改库时**漏一个就会出现"库里是 v1.1、代码里还是 v1.0"的静默错配**——诊断结果会标上错误的版本，历史评测再也对不上。

| 位置 | 形态 | 谁改 |
|---|---|---|
| `判据知识库_vX.Y.md` 的文件名与文首标题 | 人名可读 | 改写判据的人 |
| `src/lib/ai/criteria.ts` 的版本常量 | 代码 | 同一个人，**同一次提交** |

**为什么不做成自动同步**：读文件名当版本号是个隐患——文件被重命名、被复制一份、从别处拷贝进来，版本号就跟着乱。写死在代码常量里，改的时候必须动代码，反而多一道人工确认。这是一次性的、低频的动作，不值得为它建一套自动机制。

**为什么版本号不进 prompt**：模型只回填裸 ID（`S2`），`@v1.0` 由服务端拼。让模型复述版本号等于多给它一个编造的机会。详见《检索契约》§3.5。

### 3.7 裁决记录与否决记录（模板）


## 4. 已知局限与边界

### 4.1 判据测不了什么

| 条目 | 测不了 | 目前的兜底 |
|---|---|---|
| `D1` | 纯心理推进段必然判零信息（情绪转折不算"新信息"） | `notApplicable` 的功能条件化；**这是口径代价，不是 bug** |
| `P2` | 纯视觉白描只有 1 类通道，会被判不通过 | 无兜底，需要产品侧决定是否放宽（改 statement 语义，得走 A 型） |
| `M1` | 只出现 1 次的伏笔覆盖不到 | 无兜底，宁可漏不可猜 |
| `C1` `D2` | 当前完全无法判定，只能采集 | 只采集数值，标注 `draft-pending-threshold` |
| 全库 | 跨章节 / 长篇结构问题（如 5 万字小说的主线判断） | 本期限定单段 150–3000 字，不做跨章节 |
| 全库 | 主题深度、反讽、幽默、原创性 | 永久否决，见 §2.1 |

### 4.2 容易误报什么

- **结构组织**：把功能性开篇（建立空间、铺设声景）判成"缺乏动机 / 节奏拖沓"。golden set 里的两个反例样本（GC_001 边城地理开场、GC_013 回响的草场开篇）就是专门为这一条设的防线。
- **具体性与感官**：把概括性过渡句判成"空转"（`P1` 的 `commonFalsePositive`）。
- **信息密度**：把抒情段的低密度判成拖沓（`D1` / `D3` 共用这一条误报面）。
- **视角一致性**：把全知体判成"视角混乱"。必须先判是不是有限视角——这是硬前置。

### 4.3 口径纪律（对外怎么说分）

这一节是防守用的，**违反口径比判据写错更严重**：

1. **离线跑分不得称为"模型准确率"**。离线模式走 fixtures 确定性回退，测的是管线通不通，不是模型准不准。正确说法："链路可用性"。
2. **基线 0% 的说法**：`analysis-v2` 真实模型下 6/6 全部未通过校验、回退 demo——这是**链路可用性 0%**，不是"模型准确率 0%"。模型在同一 prompt 下是能输出好内容的（"外貌降级的顶点"），失效在字段形状、token 预算、强制条款这三处工程问题。
3. **单维度样本 < 5 条时不给分**，标"样本不足"。目前 14 条 golden case 全部 `reviewedBy: null`，未审定，**不计正式分数**。
4. **不许把"没召回"说成"没写"**：诊断为空时，四段面板必须显示"本次未召回知识条目"，否则无法区分知识库缺失和检索失败。

### 4.4 被追问时的标准答法

**Q：你这套维度的依据是什么？**
六个维度取 6+1 Traits 与高考作文评分标准的交集，逐条过了"有公认出处 / 可量化 / AI 可实现 / 符合定位"四关。现有 44 条标注样本可以 100% 映射回六维，说明覆盖不是靠砍出来的。

**Q：凭什么说 AI 判得了？**
有实测边界。视角聚焦这类任务，内聚焦 F1 88.7、外聚焦 84.8，但零聚焦只有 36.2——所以我们只判"一致性"，不判"聚焦类型"，全知体一律标不适用。这是照着实测数据划的边界，不是拍脑袋。

**Q：那 AI 判错了怎么办？**
两层。判据层要求每条判据能二值判定、每个反例都能冒个回代；系统层要求每条结论引用判据编号 + 逐字原文引文，引文不在原文里就在代码层丢弃。误报另有专门的反例样本做门禁。

**Q：为什么没有更多维度？**
每多一个维度就多一份不可复现的风险。我们宁可六个维度做到能复算，也不要十几个维度各说各话——项目最初就是这个状态：golden set 的 44 条标注散成 23 个自由标签，规格里另写了一版 16 维清单，两边对不上，任何一版都不能当本体用。

**Q：这些判据验证过了吗？**
规则层面验过了：18 条全部通过 4 批人工回代验收，每条例句都能按 metric 手工复算出 note 里写的结果。**合并阶段又抓出一处回代失效**——M1/M2/D3 的例句用斜杠冒充段落，而 metric 要求按换行切分，M2 正例按实现会判成"段落数 < 2 → 不适用"。已修复并补长。这件事本身是答辩素材：**回代必须按实现跑，不能靠读**。**统计层面还没验**：目前全库是 `draft`，没有一条达到 `agreed`（需要两名独立标注者 κ ≥ 0.6）。这一步要等 golden set 扩到 30–50 条并完成人工审定。
