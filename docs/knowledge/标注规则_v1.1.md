# Golden set 标注规则 v1.1

> 在 `schema.md` 之上追加。**冲突时以本文为准**。
> 目的：把「不确定怎么标」的地方变成**可量化、可验证、AI 也能判**的规则，而不是靠标注者手感。

---

## 为什么要升级

v1.0 只规定了字段形状（长度、锚点逐字、关键词长度），**没有规定「什么时候不该判为缺陷」**。
结果是同一段文本，甲标成「密度过高」，乙标成「必要铺陈」，两个人都不算错——这种标注无法支撑评测。

v1.1 的立场：**每条结论都必须能落回判据库的某一条判据，并交代该判据在本文是否适用。**
判据库（18 条，六维×3）本身已经是可执行定义：每条都有 `statement`、`checkable`、`metric`（照抄式计数规则）、`notApplicable`（不适用条件）。
所以「权威依据」不需要外借——**判据库就是这份 golden set 的法条**。

---

## R1 判据绑定（机器可判）

每条 `expectedFinding` 和每条 `forbiddenClaim` 都必须写 `criteriaIds`，取值来自判据库 18 条编号。

- 允许引用 pending 的 `C1`、`D2`（它们是「只采集不判定」，标注可以引用，但不计入自动分）
- 不许自造编号，不许写维度名代替编号

**机器判定**：`criteriaIds ⊆ {P1,P2,P3,M1,M2,M3,S1,S2,S3,C1,C2,C3,D1,D2,D3,V1,V2,V3}` 且非空。

**依据**：PRD 2.0 §3.2「必须同时命中知识库条目与用户原文定位，二者缺一判为无证据」。

---

## R2 缺陷 / 阳性二分（机器可判）

`basis` 字段，只能取两个值：

| 值 | 含义 |
|---|---|
| `defect` | 这段文本在该判据上**不成立**（真问题） |
| `positive` | 这段文本在该判据上**成立**（做到了），只用于反例样本与阳性示范 |

**反例样本（"这段几乎没问题"）的写法**：`expectedFindings` 全用 `basis: "positive"`，把"容易误报成缺陷的地方"写进 `forbiddenClaims`。

**机器判定**：`basis ∈ {defect, positive}`；且同一条 EF 的 `criteriaIds` 与之相容（`positive` 不允许配 `severity: high`）。

**这条解决了什么**：GC_027 那种「把『视角不越界』当缺陷」的错位，现在无处可藏——它只能被写成 `positive`，不会被拿去算缺陷召回。

---

## R3 不适用优先（机器可判，**这是最关键的一条**）

如果某条判据的 `notApplicable` 条件在本文成立，**不得判为缺陷**。

判据库里已有一批**纯量化**的不适用条件，程序可以直接算：

| 判据 | 量化不适用条件 |
|---|---|
| `D1` | 全文汉字数 < 200 |
| `D3` | 全文汉字数 ≤ 400 |
| `D2` | 段落数 < 2 |
| `M1` / `M2` | 段落数 < 2 |
| `S1` / `S2` / `S3` | 段落数 < 3 |
| `V1` / `V2` / `V3` | 全知体（零聚焦）—— 需判读，见下 |

**机器判定**：`basis: "defect"` 的 EF，若其 `criteriaIds` 含上述判据而本文满足对应量化条件 → **判标注错误**。

**非量化的不适用条件（如「议论段、说明段」「全知体」）**：必须由标注者写明 `notApplicableChecked`（一句话，说明本文为何**不构成**不适用），这段文字进人工复核清单，不参与自动判定。

**这条解决了什么**：GC_021「冷香丸配方算不算铺陈过长」——不再靠手感。要么它满足 D1/D3 的字数门槛与计数规则被如实标成缺陷，要么标注者必须写明为何不适用条件不成立。两种都有据可查。

---

## R4 锚点同段（机器可判）

正文**允许拼接**（跳过诗词、注释等不参与诊断的段落），但：

- 每条 EF 必须写 `anchorParagraph`（锚点所在的、**拼接后正文中的**段落序号，从 1 开始）
- `requiredAnchor` 必须逐字出现在该段落内
- EF 的 `claim` 所述事件，若只发生在另一个段落，则该 EF 无效

**机器判定**：按空行切段后，`requiredAnchor` 落在第 `anchorParagraph` 段内。

**这条解决了什么**：GC_019 那种「claim 跨两个场景、锚点只落在后半」的隐患，现在会被直接拒绝。跨场景的结论必须拆成两条，各挂自己的锚点。

---

## R5 同作品配额（机器可判）

同一作品（`source.ref` 相同，或 `source.ref` 是同一作品的不同 ID）在全集内**最多 2 条**，且两条的 `source.locator` 必须描述**不同的叙事功能段**（如「开场」「高潮」「结尾」），不许是同段不同说法。

**机器判定**：按 `source.ref` 计数；`locator` 去重后必须等于条数。

**这条解决了什么**：GC_025 与 GC_017 同出《祝福》——语感相近，模型可能靠作品先验蒙对，让分数虚高。限 2 条 + 强制不同功能段，把这种"背答案"的空间压到最小。

---

## R6 覆盖配额（机器可判，**回应「尽量涵盖全部文学、写作、文本情况」**）

golden set 必须覆盖下列维度，每条 case 在 `source` 里声明：

```jsonc
"source": {
  "kind": "user-corpus",
  "ref": "水浒传",
  "locator": "第009回·野猪林",
  "licenseStatus": "public_domain",
  "genre": "narrative-fic",     // 见下表
  "register": "classical"       // classical | modern
}
```

`genre` 取值表（必须从中选，不许自造）：

| genre | 说明 | 目标条数 |
|---|---|---|
| `narrative-fic` | 小说（叙事虚构） | ≥ 10 |
| `narrative-nonfic` | 叙事散文 / 回忆 / 传记 | ≥ 2 |
| `lyric` | 抒情散文 / 随笔 | ≥ 2 |
| `poetry` | 诗 / 词 / 韵文 | ≥ 2 |
| `drama` | 戏剧 / 对白体 | ≥ 1 |
| `argumentative` | 议论 / 评述 | ≥ 3 |
| `expository` | 说明 / 科普 / 实用文 | ≥ 2 |

同时必须满足：

- **`sourceKind` 两种都要**：`narrative` ≥ 10、`argumentative` ≥ 3（当前 `argumentative` 为 0，是明显缺口）
- **长度三档**：汉字 < 300（用于验证 `D1/D3/S1` 等不适用条件被正确触发）≥ 2 条；300–1000 ≥ 8 条；1000–3000 ≥ 4 条

> **短样本的豁免**：v1.0 规定正文 ≥300 汉字，但「验证不适用条件」这一类样本天然要短。
> 因此 `汉字 < 300` 的样本**不受 300 字下限约束**，前提是 `annotation.notes` 里写明
> 「本样本用于验证 X 判据的不适用条件」，并且该样本的 `basis` 不得引用被排除的那几条判据。
> 除此之外的样本一律遵守 300–3000。
- **质量两档**（**修订**：v1.1 初稿写的"三档"是我拍脑袋加的，与既有标注的真实语义不符，已废弃）：
  - **反例样本 ≥ 3 条**：文本写得成立，用于检验**误报**。这些 case 的 `forbiddenClaims` 才是主角。
  - **缺陷样本 ≥ 3 条**：文本本身有明显问题（堆砌、空转、视角越界、结构散），用于检验**漏报**。
    这是当前集子里最缺的一类——42 条里一条都没有，等于只测了"看得出好"，没测"挑得出坏"。
  - 其余样本为普通样本，不作配额要求。

> 关于 `basis` 的说明：既有样本的 `expectedFindings` 大多是**写作手法观察**
> （如"长衫降级成破夹袄承担了坠落信息"），既不是缺陷也不是"做到了"。
> 因此 `basis` 只用于**区分反例/缺陷两类专项样本**，普通样本按实际语义填写即可，
> 不要求"全 positive"或"全 defect"。

**机器判定**：按上表统计，逐项报缺口。

**这条解决了什么**：现在的 30 条全是叙事小说、全是 `narrative`，等于**只在这一个文本类型上证明了模型能力**。产品对外宣称"文学诊断"，评测却只覆盖小说，面试官一问就露。配额表把这件事变成可核对的数字。

---

## 执行顺序

1. 先按 R6 补齐文本类型缺口（内容工作）
2. 再按 R1–R5 给全部 case 补字段（内容工作）
3. 我的机器检查器（`scripts/check-golden-schema.mjs`）逐条拦截
4. 通过机器检查后，才进人工审定；`reviewedBy` 由人填

**注意**：R1–R6 未满足的 case 一律视为 `draft`，不参与正式计分。这条不让步。
