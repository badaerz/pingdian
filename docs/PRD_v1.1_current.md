# 故事熔炉 Story Forge
## 产品需求文档 v1.2（当前实现版）

更新时间：2026-08-21  
文档性质：以当前代码、测试和 Demo 流程为准的产品现状与验收文档

## 1. 文档结论

Story Forge 是面向中文大学生创作者、文学教师与数字人文学习者的 AI 辅助创作与文学分析 Web Demo。产品核心不是“一键代写”，而是把灵感、人物、世界观、蓝图、正文、文学分析和训练反馈组织为可确认、可回溯的工作流。

本版本的实现边界：

- P0 主链路已经可以在本地离线运行：项目桌面 → 创作台 → 文学诊断/为什么这样写 → 知识图谱 → 写作训练。
- AI 服务通过服务端 `/api/ai` 统一调用；没有密钥或外部服务失败时提供结构化 Demo 回退。
- RAG 已接入公开/授权知识源、来源状态、向量/关键词检索和任务预算；用户私有文本只在当前分析请求中使用，不进入产品数据库。
- DeepSeek 实时烟测已完成一次；ModelScope 已成功创建远端任务但在当前超时边界内未返回图像，随后按契约回退 Demo；Supabase 公开 RAG 仍需部署后网络验证。

## 2. 产品定位与原则

### 2.1 定位

文学创作流程工具 + 数字人文文本分析工具 + 过程性写作训练工具。AI 是可解释的协作者，不是替用户提交成稿的替代者。

### 2.2 核心原则

1. 用户掌握最终决定权：AI 候选、续写和训练反馈均需用户主动确认，AI 不直接覆盖正文。
2. 证据优先：文学分析、知识图谱和训练反馈必须绑定原文片段、来源或回答证据；无法绑定时 fail-closed 或降级提示。
3. 上下文一致性：人物、世界观、蓝图和章节上下文在多轮创作中形成可检查的上下文快照；发现性格、设定或关系矛盾时提示并允许用户修复。
4. 零数据保留与安全：用户作品、训练记录和生成资产只保存在当前浏览器；浏览器不创建云端账户，服务端密钥不下发，私有文本不进入产品数据库或公共知识库。
5. 版权与学术规范：仅展示已核验公版/授权短片段；不传输题库完整示例答案；训练只反馈方法和证据，不代写。
6. 学术级可视化：知识图谱采用力导向、分层、同心布局、中心性指标、证据抽屉和表格替代视图，不做普通思维导图。

## 3. 目标用户与主要任务

| 用户 | 主要任务 | 成功信号 |
| --- | --- | --- |
| 大学生创作者 | 建立故事设定、续写、检查人物/世界观一致性 | 能回看上下文、确认候选并继续写作 |
| 文学/写作教师 | 展示分析证据、课堂技法、过程性训练 | 能切换课堂演示，查看方法而非答案 |
| 数字人文学习者 | 上传文本，观察关系、结构、主题和语言数据 | 看到图谱、情节曲线、主题热力图与证据 |
| 评委/演示观众 | 在短时间看到技术深度 | 上传作品后得到多视图分析和具体建议 |

## 4. 信息架构与演示路径

### 4.1 页面模块

- 项目桌面：项目索引、案例入口与“仅存本地”状态。
- 创作台：灵感、人物、世界观、蓝图、正文编辑、候选确认、版本抽屉、多轮方向对话。
- 文学诊断：人物关系、情节结构、主题演变、语言风格、为什么这样写、证据抽屉、主题热力图。
- 知识图谱：经典知识库与“我的文本”双模式，叙事/论述分析，学术画布、表格、筛选、中心性、来源状态和证据详情。
- 写作训练：六道练习、个人练习/课堂演示、严格过程反馈、版本差异、历史链和六维成长趋势。
- 设置：AI 状态、隐私、调用预算、导出和危险操作。

### 4.2 推荐 Demo 顺序

1. 从项目桌面进入“回响的草场”主案例。
2. 在创作台编辑人物或世界观，展示 AI 续写前的上下文一致性提示。
3. 进入文学诊断，展示四域分析、证据抽屉、“此处铺垫不足”和主题热力图。
4. 从诊断卡点击“去专项训练”，展示合法练习直达；无效练习 ID 会安全回退。
5. 在知识图谱上传 TXT/MD 或粘贴当前项目文本，展示 Gephi/Palladio 风格布局、指标、证据和表格替代。
6. 在写作训练提交一次答案，展示 v2 反馈、证据逐字校验、前后版本差异和六维趋势。

### 4.3 数字人文现场演示场景

以“学生上传一篇课程作业”为入口，评委可以看到同一份文本被转换成三种互补证据：

1. 人物关系图：节点代表人物，边代表交互关系，边的证据可回到原文片段；真实频率和关系类型由结构化分析结果决定，不用装饰性连线。
2. 情节节奏曲线：横轴是章节/段落，纵轴是冲突或叙事张力，关键转折点附带原文证据。
3. 主题演变热力图：横轴是章节，纵轴是主题/意象，颜色表示分布密度，并可打开来源详情。
4. 具体诊断：例如“此处铺垫不足”，必须同时给出位置、原文引用、影响、置信度和下一步训练入口。

该场景是 Demo 的讲解脚本，不代表平台拥有未授权的完整教材文本。演示文本应使用用户上传作品或已核验公版/授权片段；课程作业 PDF 导出和教师班级分布看板属于后续版本。

### 4.4 创作 - 学习飞轮

```
灵感 → 人物/世界观 → 蓝图 → 正文 → 文学诊断
  ↑                                      ↓
下一次方向 ← 六维成长趋势 ← 写作训练 ← 为什么这样写
```

当前 Demo 已实现诊断卡到专项训练的安全直达、训练版本链和六维趋势；“能力徽章”“教师班级分布”和自动把训练能力写回续写提示仍属于 P1 后续增强。

## 6. AI、RAG 与数据边界

### 6.0 轻量可扩展架构

| 层 | 当前职责 | 可扩展壁垒 |
| --- | --- | --- |
| 应用层 | 创作台、文学诊断、知识图谱、写作训练 | 用户确认、证据回溯和工作流体验 |
| 任务层 | 灵感、人物一致性、文学分析、训练反馈、生图参数推荐 Prompt | 文学理论与 AI 工程的任务封装 |
| 知识层 | 作品 - 作者 - 主题 - 时代 - 技法 - 意象 Schema、RAG 来源与证据 | 可接入高校授权目录和批量元数据 |
| 模型层 | DeepSeek/ModelScope 等第三方服务端 API | provider 可替换，不把产品价值押在单一模型 |

产品的技术选择是“轻量但可扩展”：不自研基础大模型，把工程投入集中在文学任务、证据协议、上下文一致性和可视化工作流。

### 6.1 AI 协议

统一服务路由支持 analysis、analysis-v2、explain、mentor、story-direction、consistency-check、knowledge-extract、image-parameter-recommendation、training-feedback-v2 等任务。每个任务有输入长度、预算、证据和结构化 validator；无法通过 validator 的响应不写入作品状态。

### 6.2 RAG

RAG 由来源目录、来源状态、关键词/向量检索、任务预算和证据 ID 组成。公开/授权材料可进入检索；pending 或 summary-only 来源只允许摘要/技法信息，不发送受限原文。用户上传 TXT/MD 和当前项目文本是单次请求输入，不进入公共知识库或产品数据库；“我的文本”图谱只保存在当前页面内存，项目分析快照仅留在浏览器 StoryState。

### 6.3 零数据保留

- 浏览器不持有 DeepSeek、ModelScope 密钥，也不创建 Supabase client 或匿名账户；密钥来自服务端环境变量。
- 项目、人物/世界观、蓝图、正文、分析快照、训练历史和 AI 候选元数据保存在 `localStorage`；确认保存的生成图片保存在 `IndexedDB/story-forge-assets`。
- 设置页“一键清除本地创作数据”会移除所有 `story-forge:*` 存储、旧版 Supabase auth token 和生成资产数据库，然后恢复编译进应用的内置答辩案例。
- 清除浏览器的“该站点数据/网站存储”也会删除作品；只清除 HTTP 图片与脚本缓存通常不会删除 localStorage/IndexedDB，界面不得笼统写成“清缓存”。
- Supabase 只保留公开/授权文学知识库。迁移 `004_zero_user_data_retention.sql` 删除旧版 `projects`、`ai_runs`、`training_attempts`；浏览器端不存在这些表的读写接口。
- 用户内容 API 返回 `Cache-Control: no-store`，服务端不把正文或响应写入产品数据库。第三方模型供应商的单次请求处理遵守其自身条款；产品不替供应商作零留存承诺。
- 内置答辩项目 `demo`、`demo-demo_002` 的档案结构始终不可删除；加载存储时会恢复 canonical 的项目、章节、人物、世界观、蓝图、版本和上下文基线。`NEXT_PUBLIC_DEMO_LOCKED=true` 时额外关闭 DeepSeek、ModelScope 和公开向量检索，并让正文与实体编辑器只读；分析、候选和证据展示仍可运行。

## 7. 非功能与技术验收

| 类别 | 当前验收 |
| --- | --- |
| 易用性 | 首屏可进入项目桌面；模块入口保留现有名称；移动端折叠菜单和底部导航存在 |
| 性能 | AI 过程在触发控件附近显示；服务端有超时/预算；上传和下载有大小/时长上限 |
| 可靠性 | API 失败提示、重试、Demo 回退；异步请求有 AbortController/序列令牌；旧响应不能覆盖新状态 |
| 安全 | API 密钥只在服务端；浏览器无云端用户会话；用户内容 API no-store；URL 下载严格 HTTPS/host/suffix 白名单；外部文本不持久化 |
| 可解释性 | 分析结论绑定 evidenceIds/观察证据；知识图谱显示来源状态与详情；训练证据逐字校验 |
| 可维护性 | AI task、validator、RAG、store、视觉 token 分层；模块可独立扩展 |
| 视觉 | logo 适配纸白/深墨/森林绿/铜金；GSAP ScrollTrigger 只使用 transform/opacity；支持 reduced-motion |

## 9. 取舍与后续路线

### P0：交付前必须保持

- 创作台正文可编辑、候选需确认、上下文一致性不崩。
- 文学诊断和知识图谱的证据链、来源状态、失败关闭。
- 训练 v2 不代写、版本链和课堂模式。
- 服务端密钥、RAG 隐私、错误回退。
- 答辩前启用 `NEXT_PUBLIC_DEMO_LOCKED=true`，使用全新浏览器配置文件走主案例，不在内置项目上做持久编辑。

### P1：下一轮增强

- Supabase 公开 RAG、ModelScope 最终图像返回的部署 smoke test 与外部服务监控。
- verified/authorized 经典片段逐条版权核验和来源页。
- 教师教研看板、匿名课堂样例、批量训练对比。
- 浏览器视觉回归截图与滚动性能指标。
- 面向高校写作课的教师教研看板、班级维度统计和可复用课堂案例。

### P2/P3：明确不纳入当前 Demo

- 视频生成、完整多媒体资产包、校园社区、机构版权限体系。
- Vue 页面迁移。当前项目是 Next.js/React；本轮采用 GSAP+ScrollTrigger，避免双框架运行时。

## 10. 评委 Demo 口径

“故事熔炉不是帮学生交作业的生成器，而是一套把文学创作、文本证据和过程训练连接起来的叙事智能工作台。评委可以上传一篇文本，看到人物关系、情节节奏和主题演变；再进入具体诊断和训练，系统会指出证据和下一步实验，并在续写前检查人物与世界观是否保持一致。”

| “首版知识源数量有限，能叫知识图谱吗？” | 首版验证的是可扩展 Schema、来源状态、证据闭环和分析工作流；数据规模会通过高校授权目录和公开元数据合作扩展，不把 Demo 样本包装成完整数据库。 |
| “和通用 AI 写作工具有什么区别？” | 通用工具以生成文字为中心；Story Forge 以中文文学教育、过程性反馈、上下文一致性和可解释分析为中心。 |
| “AI 会不会替学生写作业？” | 训练 v2 禁止 replacement/prose，反馈只能引用用户回答或核验来源短引；课堂模式禁用提交和历史写入。 |
| “为什么不自己训练大模型？” | 模型层可替换，产品壁垒在文学任务 Prompt、RAG Schema、证据协议、上下文工程和教学工作流，不重复建设基础模型。 |
| “能不能直接导出课程作业 PDF？” | 当前可导出 Markdown/TXT；PDF 排版、教师看板和班级统计是后续版本，当前 Demo 不虚构已完成能力。 |
