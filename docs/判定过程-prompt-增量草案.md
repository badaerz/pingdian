# 判定过程的提示词增量草案

**状态：已上线（2026-11-21，用户批准）。** 原文保留在此作为变更记录；实际生效位置是
`src/lib/ai/tasks.ts` 的 `analysis-v2` 提示词末尾。

拟添加到 `analysis-v2` 提示词的诊断输出要求中。草案正文如下。

> 每条 `diagnostics` 可附带 `criteriaEvaluation`。对这条诊断实际使用且适用的判据，依据本次注入的 `checkable` 与 `metric` 核对原文。只记录规则中的可核对计算与结论。
>
> 每条记录包含四个字段。
>
> - `criteriaId` 填本次实际使用的判据裸 ID，例如 `P1`，每个判据最多填写一次。
> - `countedAt` 填 1 至 20 个唯一的原文证据 ID。这些 ID 必须已列入本次返回的 `evidence`，且各自指向可核对的 `observation` 或 `user` 原文引文。按规则注明计数单位。一条引文可能支撑多个计数项，多个引文也可能共同支撑一个计数项。
> - `reason` 使用简短的核对记录，逐项说明哪条证据对应哪项计数、算出的数值以及适用的阈值。引用原句的词或短语时保留原文。无法从证据支持计数或结论时，省略这条记录。
> - `result` 依据判据规则填写 `pass` 或 `fail`。达标填 `pass`，未达标填 `fail`。
>
> 没有可核对记录时省略 `criteriaEvaluation`，照常返回诊断。判据不适用或阈值待定时，省略对应记录。

以下示例仅用于展示 JSON 结构，假设 `ev_003` 与 `ev_007` 各指向原文中的一整句。

```json
{
  "criteriaEvaluation": [
    {
      "criteriaId": "P1",
      "countedAt": ["ev_003", "ev_007"],
      "result": "fail",
      "reason": "ev_003 的「孤独而苍凉。」命中「孤独」「苍凉」，ev_007 的「沉重而压抑。」命中「沉重」「压抑」。两句各有 2 个抽象评价词和 0 个具体名词，共命中 2 句。达标要求为 0 句。"
    }
  ]
}
```
