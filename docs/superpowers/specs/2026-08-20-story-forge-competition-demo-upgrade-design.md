# Story Forge 竞赛 Demo 全面升级设计

## 1. 目标与成功标准

本轮将 Story Forge 从“具备创作、分析、知识与训练入口的 MVP”升级为可在竞赛现场完整演示的数字人文创作工具。核心差异不是单纯生成文字，而是让评委看到四条可验证的产品能力：

1. 用户能通过多轮讨论控制故事走向，AI 只在明确指令后生成可确认的正文候选。
2. 系统能读取人物、世界观、蓝图和既有正文，发现续写中的上下文矛盾并给出证据。
3. 用户上传文本或从创作台送入作品后，系统能生成有证据支撑的人物/概念关系、节奏、主题演变和具体诊断。
4. 文学诊断能把问题送入专项训练，形成“创作—诊断—训练—再创作”的闭环。

完成标准不是页面出现了控件，而是核心链路有真实数据、严格校验、离线兜底、显式状态和自动化测试。所有 AI 结果都标记 `live` 或 `demo`，不得把演示数据表述为实时模型结论。

## 2. 已确认的产品原则

- 离线优先：项目和核心创作状态先保存在本机；云端同步是增强能力，不是基本使用前提。
- 服务端 AI：DeepSeek、ModelScope 和其他密钥只存在于服务端环境变量，不进入浏览器包或本地项目文档。
- 用户确认：AI 生成内容先成为可编辑候选；只有用户明确确认后才写入作品。
- 证据优先：文学诊断、训练反馈、上下文冲突和知识图谱关系都必须关联原文证据。
- 不代写课堂作业：训练模块只给过程反馈、局部方向和启发式问题，不生成可直接提交的完整答案。
- 版权审慎：经典文本分为“已核验、待核验、仅结构化摘要”，未核验作品不展示或训练长文本。
- 学术可视化：采用 Gephi、Palladio 式的数据画布、筛选、图例、指标和证据联动，不制作普通放射状思维导图。
- 品牌统一：以新 Logo 的纸白、深墨和铜金为主视觉，靛蓝表达知识与证据，森林绿表达成功和可执行状态。

## 3. 范围与优先级

### 3.1 本轮必须完成

- 修复并验证 ModelScope 图片生成轮询链路。
- 图片生成参数编辑与 AI 参数推荐。
- 创作台多轮故事方向讨论、每轮默认方向标签、讨论转续写候选。
- 续写前后的上下文一致性检查和冲突确认。
- 严格证据化的完整文学诊断与“为什么这样写”。
- 创作台作品直达文学诊断。
- 上传 TXT/MD 或粘贴文本生成学术关系图、节奏曲线、主题演变热力图和具体建议。
- 知识图谱的“我的文本”分析模式。
- 写作训练实验室闭环和轻量成长视图。
- 全站视觉与新 Logo 适配。
- 最终按实际产品改编 PRD，并完成结构、内容和视觉核验。

### 3.2 明确不扩张

- 不建设教师账号、班级、课程发布和作业管理后台。
- 不建设社区、商业化、机构账号、短视频和完整 IP 资产流水线。
- 不训练自有基础大模型。
- 不把尚未实现的向量字段描述成完整 RAG；本轮允许继续使用结构化与关键词检索。
- 不允许 AI 自动覆盖正文，也不因高风险冲突永久阻止作者接受候选。

## 4. 统一 AI 任务协议

现有 `/api/ai` 保留为统一服务端入口，新增任务类型但不为每个按钮创建零散接口。所有任务使用同一响应包络：

```ts
interface AiEnvelope<T> {
  mode: "live" | "demo";
  task: AiTask;
  requestId: string;
  contextRevision?: number;
  result: T;
  warnings: string[];
}
```

新增或升级的任务：

- `story-direction`：多轮讨论，只返回判断、风险、追问和推荐标签，不返回正文候选。
- `continue`：将已确认的讨论摘要转成 2-3 个正文候选。
- `consistency-check`：检查人物、世界规则、蓝图事件和时间线冲突。
- `analysis-v2`：返回完整诊断、证据、关系、节奏、主题和语言结果。
- `knowledge-extract`：从用户文本提取实体、关系和证据。
- `image-parameter-recommendation`：根据项目或临时文本返回可编辑参数草案。
- `training-feedback-v2`：按练习量规输出逐证据过程反馈。

每个任务拥有独立的运行时校验器。不能再以“字段存在”作为通过标准；数组长度、枚举、数值范围、证据引用、候选数量和上下文修订号都必须校验。不合格的在线结果进入明确的演示兜底，并返回可见警告。

## 5. 数据与持久化

项目存储从当前版本迁移到下一版本，迁移函数只补默认值，不破坏已有项目：

- `dialogueThreads`：按项目保存多轮故事方向对话、标签、讨论摘要和时间。
- `imageGenerationSettings`：保存正向提示词、负向提示词、模型、尺寸和服务端允许的高级参数。
- `analysisSnapshots`：保存从当前项目生成的分析结果、来源修订号和时间；外部上传默认不持久化。
- `consistencyReports`：保存候选对应的冲突结果、严重级别和用户确认状态。
- `trainingAttempts`：增加练习版本、量规得分、来源诊断 ID 和前后版本关系。

用户临时上传的 TXT/MD 只保存在当前浏览器会话内，不写入 Supabase。上传区清楚说明用途、字符上限和保存边界。

## 6. 创作台：多轮故事方向讨论

创作台增加“与 AI 讨论下一步”对话区，不再点击一次就直接生成剧情候选。每一轮提供可组合的默认标签：

- 跌宕起伏
- 轻松日常
- 推进冲突
- 深化人物关系
- 埋设悬念
- 强化情感

用户可以选择标签并补充自由文本。AI 每轮只返回：当前理解、一个推荐方向、潜在一致性风险、一个细化问题和下一轮推荐标签。对话可以持续多轮。

只有用户点击“生成续写”后，系统才把对话摘要和项目上下文发送给 `continue`，生成独立候选。候选仍需用户接受、编辑或拒绝；生成后如果项目修订号已经变化，候选标记为过期，不可静默应用。

## 7. 上下文一致性机制

一致性采用两阶段检查：

1. 生成前：把锁定人物、锁定世界规则、当前蓝图节点、相邻章节摘要和关键时间线放入上下文包。
2. 生成后：对每个候选单独运行一致性检查，比较候选陈述与锁定事实及既有证据。

冲突项结构：

```ts
interface ConsistencyFinding {
  id: string;
  category: "character" | "world" | "plot" | "timeline";
  severity: "low" | "medium" | "high";
  expectedFact: string;
  candidateQuote: string;
  priorEvidence: string;
  suggestion: string;
}
```

高风险冲突不会永久禁止作者使用候选，但接受按钮改为“审阅冲突”。用户展开证据并再次确认后才能应用。人物卡、世界观卡和蓝图锁定状态仍由用户控制，AI 不自动修改设定。

## 8. 文学诊断与“为什么这样写”

### 8.1 输入来源

- 当前创作项目。
- 创作台选中文本。
- 粘贴文本。
- TXT/MD 临时上传，默认上限 20,000 字符。

创作台提供“送去文学诊断”入口，携带项目 ID、当前章节或选区，并在诊断页显示来源和修订号。

### 8.2 分析维度

- 人物关系：人物目标、行动、关系类型、关系变化和证据。
- 情节结构：事件节点、节奏强度、转折、铺垫和回收。
- 主题演变：主题在文本分段中的显著程度与变化理由。
- 语言风格：句长、对话比例、感官密度、修辞、叙事距离和语言节律。
- 具体诊断：位置、原文引用、影响、建议动作和置信度。

系统先判断文本类型。叙事文本生成“人物—事件—主题”关系和情节节奏；议论文、学生作文或非虚构文本改用“概念—论点—证据”关系和论证推进曲线，禁止为了满足图谱样式而虚构人物。

### 8.3 证据校验

所有观察型结论必须包含可在输入文本中精确找到的引用。服务端校验引用内容和位置；无法匹配的条目被剔除或降为“推断”，不得显示为原文事实。点击“此处铺垫不足”等建议时，关系图、节奏曲线、主题热力图和证据面板同步定位。

“为什么这样写”继续支持选区分析，但输出拆分为：核心判断、原文证据、技法、阅读效果、上下文一致性、可尝试实验和参考知识。知识参考与文本观察必须使用不同来源标记。

## 9. 学术级可视化与知识图谱

### 9.1 视觉结构

可视化使用深墨研究画布、铜金焦点、靛蓝来源与低饱和节点色。界面包含：

- 力导向、同心或分层布局切换。
- 节点类型与边类型图例。
- 类型、关系、置信度和文本区段筛选。
- 节点度数、中心性和连接数量等基础指标。
- 缩放、平移、适配画布、重置和列表替代。
- 右侧证据档案面板，显示原文、关系说明、置信度和来源。

禁止装饰性轨道、持续发光和放射状思维导图。移动端默认列表与证据优先，图谱作为可切换视图。

### 9.2 知识图谱双模式

- “经典知识库”：继续展示已核验的作品、作者、主题和技法关系。
- “我的文本”：从当前项目、粘贴文本或 TXT/MD 提取人物、地点、事件、主题、意象、技法和概念。

所有上传文本关系都带原文证据。经典知识库先保留结构化和关键词检索；向量字段只作为后续能力，不在产品或 PRD 中宣称已经实现 RAG。

### 9.3 轻量真实 RAG

本轮将“后续能力”升级为可验证的轻量 RAG，但不引入自建模型或新的托管向量服务。检索链路如下：

1. 种子导入把作品摘要、技法解释、短片段和结构化案例切成带 `work_id`、`chunk_type`、`source_status`、`source_url`、`quote` 和字符区间的片段。
2. 服务端通过配置的 embedding provider 生成 384 维向量；如果 provider 未配置或返回失败，保留结构化关键词索引并标记 `retrievalMode: "keyword"`。
3. Supabase `match_literature_knowledge` RPC 执行余弦相似度检索，并在服务端再次过滤版权状态、作品来源和任务允许的片段类型。
4. 任务上下文只注入排名靠前且带来源的片段，统一携带 `retrievalId`、相似度、来源状态和原文引用；模型不得把检索片段当成用户文本观察。
5. 分析、导师解释、训练反馈和图片参数推荐可以使用检索结果，但必须在输出中区分 `observation`、`inference` 和 `knowledge`。

RAG 的验收必须包含：相同查询优先命中相关技法片段；来源状态为“待核验”的片段不会进入仿写长文本上下文；RPC 不可用时关键词检索仍能返回结果；无密钥环境不会因为 RAG 失败而阻断离线演示。产品文案和最终 PRD 显示真实的 `向量检索 / 关键词兜底` 状态，不宣称自有模型或完整生产级 RAG。

## 10. 图片生成与参数推荐

### 10.1 API 修复与能力发现

ModelScope 的创建任务已经可以返回任务 ID，但应用当前在后续轮询阶段降级到演示模式。本轮先为状态字段差异、结果地址字段、失败状态和超时增加契约测试，再修复轮询兼容，不通过重复真实生成试错。

新增 `GET /api/assets/capabilities`，仅返回服务端白名单中的模型、尺寸和可编辑参数范围，不返回令牌、内部地址或任意模型透传能力。

### 10.2 参数编辑区

- 正向提示词。
- 负向提示词。
- 模型选择。
- 尺寸/比例。
- ModelScope 当前模型真实支持并经服务端允许的高级参数。

前端只渲染能力接口允许的参数，避免出现“看似可调但服务端忽略”的假控件。

### 10.3 AI 推荐参数

推荐来源可选择当前项目或临时 TXT/MD。AI 返回参数草案、每项理由和置信提示；用户可“全部应用”或逐项应用，应用后仍可编辑。推荐不会自动覆盖当前设置，也不会自动发起付费生成。

生成结果继续作为候选资产，用户明确保存后才进入项目。实时失败时显示失败阶段、重试入口和演示兜底说明。

## 11. 写作训练实验室

采用“方案 B：创作—诊断—训练闭环”，不扩张为完整教学管理系统。

### 11.1 训练内容

保留现有四项训练：展示而非告知、人物行动、对话潜台词、冷峻白描；新增场景空间与氛围、铺垫与回收。每项包含目标、约束、量规、来源状态和禁止代写规则。

### 11.2 训练流程

1. 用户自主选择训练，或从文学诊断建议跳转到对应专项训练。
2. 系统显示技法目标、已核验参考和练习约束。
3. 用户提交初稿。
4. AI 按量规返回原文证据、优势、问题、下一步实验和启发式问题。
5. 用户修改并再次评价。
6. 系统显示前后文本对照和量规变化，不给出完整替代稿。

反馈中的观察引用必须存在于用户答案。量规得分用于同一用户自己的前后比较，不表述为绝对文学质量排名。

### 11.3 成长与课堂展示

轻量成长面板聚合具体性、人物塑造、场景感、潜台词、结构铺垫和语言控制等维度，只在有足够练习记录时显示趋势。

课堂演示模式使用无干扰布局并排展示参考文本、技法标注、匿名练习、过程反馈和修改变化。它不新增教师账号、班级或作业发布能力。

## 12. 全站品牌视觉升级

视觉升级在功能和数据协议稳定后统一进行，覆盖 `/`、项目桌面、新建项目、创作台、文学诊断、知识图谱、训练、IP 实验室和设置。

正式产品命名固定为中文“故事熔炉”、英文“Story Forge”；旧页面或旧规格中的“故事锻造”不再作为产品中文名。正式位图源为 `public/brand/story-forge-full-logo-20260820.png`，所有衍生尺寸都从该文件确定性裁切或缩放，不重新生成、不重绘图形。

Logo 使用三种同源资产：

- 完整标识：首页、项目桌面和重要空状态。
- 从正式 Logo 确定性裁切的中央书本/熔炉图形：应用导航和 favicon。
- 单色小尺寸版本：极小图标和低对比背景。

色彩以 Logo 的纸白 `#FCF6EC`、深墨 `#191E24`、铜金 `#D37302` 为主；靛蓝只用于知识和证据，森林绿只用于成功和可执行状态，氧化红只用于错误与冲突。禁止渐变背景、装饰光球、过度圆角和卡片套卡片。

关系线、节点和轨道语言只在图谱、流程、证据关系和状态连接中使用，不作为无意义背景装饰。所有页面在桌面、平板和移动端检查溢出、遮挡、文字换行、触控尺寸和导航可达性。

## 13. 错误、隐私与可解释状态

- AI 请求显示“准备上下文、发送任务、校验结果、整理结果”阶段；这是产品阶段，不伪装为模型内部精确进度。
- 所有失败保留用户输入，提供重试和离线兜底，不导致页面崩溃。
- 临时上传在界面中说明“当前会话使用、不写入项目/云端”。
- 匿名 Supabase 同步在设置和首次使用说明中明确呈现。
- AI 生成或分析结果带模式、时间和来源；导出时保留 AI 辅助标记。
- 未核验版权状态不展示长文本，不用于模仿特定在世作者风格。

## 14. 测试与验收策略

### 14.1 单元与契约测试

- AI 各任务的有效结构、无效结构、证据不匹配和离线兜底。
- 项目存储迁移、对话历史、分析快照、一致性报告和训练版本链。
- ModelScope 创建、轮询、成功、失败、超时和结果字段兼容。
- 图片能力接口白名单和密钥不泄露。
- 知识/分析图谱实体与关系证据校验。
- 训练反馈量规和引用校验。

### 14.2 组件与流程测试

- 多轮方向讨论不会直接修改正文。
- 点击“生成续写”才产生候选，确认后才写入正文。
- 高风险一致性冲突需要再次确认。
- 创作台可直达分析并带入当前文本。
- 上传文本可得到图谱、曲线、热力图和可定位建议。
- 诊断建议可跳转到对应训练，修改前后可比较。
- 图片推荐只更新草案，不自动生成或保存。

### 14.3 端到端与视觉验收

- 运行 lint、TypeScript、Vitest、生产构建和 Playwright 核心流程。
- 对全部页面生成桌面、平板、移动截图并人工检查。
- 对图谱画布检查非空像素、节点可见、筛选、缩放、详情联动和列表替代。
- 至少执行一次配置有效时的 ModelScope 实时链路；如服务端不稳定，记录创建、轮询与失败阶段证据，不虚报成功。
- 至少执行一次 DeepSeek 在线分析/对话链路和一次无密钥离线兜底。

## 15. 实施顺序

1. 建立严格数据结构、运行时校验、存储迁移和测试夹具。

## 17. 受保护契约与回退

- 保留现有路由和项目 ID，不更改用户能打开既有项目的能力。
- 保留候选确认、版本回退、导出、匿名隔离和本地优先边界。
- 存储迁移只向前补字段，任何迁移失败都回退为默认新字段而不删除旧数据。
- 外部文本会话失败不污染项目文档。
- 视觉改动按页面分层，可独立回退，不影响 API 与数据结构。
- 不清理、覆盖或重置当前工作区中的其他未提交改动。
