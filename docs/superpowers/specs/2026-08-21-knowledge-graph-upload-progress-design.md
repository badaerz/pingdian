# 知识图谱文本上传与生成进度设计

## 目标

修复知识图谱“我的文本”流程中上传文本后用户无法确认是否已生成图谱的问题，并在分析按钮附近显示可访问的生成进度。

## 已确认根因

当前上传读取和 `/api/ai` 请求均可完成；无密钥或模型返回结构不合规时，服务端会返回经过校验的离线演示图谱，同时附带“已使用离线演示结果”告警。页面将该告警使用错误样式展示，且没有 `AiProgress`，因此用户会把“已生成图谱 + 离线降级说明”误判为失败。

## 方案 A（已选择）

- 在“分析文本”按钮下方渲染已有 `AiProgress`，状态覆盖 loading、success、error。
- 进度条标签使用“知识图谱生成进度”，阶段沿用准备上下文、检索资料、生成内容、校验整理。
- 成功生成图谱后，即使接口有离线降级 warning，也把 warning 作为中性状态提示展示，不使用错误色。
- 中性提示明确说明：图谱已基于本次上传文本生成；离线/模型降级只影响生成来源，不否定本次结果。
- 真正请求失败、响应缺少图谱、上传读取失败仍使用错误状态和错误文案。
- 不把本次文本写入项目状态或云端；不改变图谱证据链和 Cytoscape 行为。

## 数据流

上传文件 -> UTF-8 解码 -> `myText` -> 点击分析 -> `/api/ai` knowledge-extract -> `extractTextGraph(sourceText, result)` -> `myGraph` -> AcademicGraph。

UI 状态增加一个独立的 `myNotice` 或等价的中性 warning 状态，避免复用错误状态 `myError`。

## 验收标准

1. 上传 TXT/MD 并点击分析后，生成图谱节点/关系可见。
2. 分析期间存在 `role=progressbar` 且标签为“知识图谱生成进度”。
3. 成功结果带 warning 时，图谱仍可见，提示为 status 而非 alert。
4. 响应无图谱或网络失败时，仍显示 alert 错误。
5. 文本不写入 StoryProvider/localStorage。
6. 现有知识图谱、上传校验和 Cytoscape 图谱切换测试保持通过。
