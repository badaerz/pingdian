**更新时间**：2026-08-22  
**产品状态**：`v0.1.0-rc.1` 发布候选  
**固化提交**：`af14bc7511e4a6b14b67391197bebce925165f85`

## 1. 一句话结论

故事熔炉不是一键代写工具，而是一套面向中文创作者、文学教师和数字人文学习者的叙事智能工作台：用户可以在浏览器中建立故事设定、与 AI 多轮讨论走向、确认后采纳候选文本，再把作品转成有证据链的人物关系、情节节奏、主题演变和写作训练反馈。

当前交付的核心价值闭环是：

```text
灵感 → 人物 / 世界观 → 蓝图 → 正文 → 文学诊断 → 为什么这样写
  ↑                                             ↓
  └──────── 六维写作训练 ← 上下文一致性 ←──────┘
```

## 3. 产品定位与设计原则

### 3.1 产品定位

- **文学创作流程工具**：把灵感、人物、世界观、蓝图和正文放入一个可回退的工作流。
- **数字人文文本分析工具**：把一段文本转为关系图、节奏曲线、主题热力图、语言风格指标和证据抽屉。
- **过程性写作训练工具**：反馈方法、证据和下一步实验，不直接提供可提交的替代成稿。

### 3.2 六项原则

1. **用户最终确认**：AI 输出先进入候选区，用户确认后才改变正文。
2. **上下文一致**：人物性格、世界规则、蓝图和章节上下文形成可检查的快照；发现矛盾时提示并允许修复。
3. **证据优先**：分析结论、图谱节点、曲线标记和训练反馈尽量绑定原文、检索来源或用户回答。
4. **本地优先**：用户创作内容默认只保存在当前浏览器；清除网站数据即可清除作品。
5. **服务端保密**：部署方的 DeepSeek 和 ModelScope 密钥只能位于服务端环境变量。
6. **学术级可视化**：知识图谱使用力导向、分层、同心布局、中心性指标、证据抽屉和表格视图，不做普通思维导图。

## 4. 用户与核心任务

| 用户 | 核心任务 | 成功信号 |
| --- | --- | --- |
| 大学生创作者 | 建设故事设定、讨论下一步走向、续写并检查一致性 | 能回看上下文，确认候选后继续写，不被 AI 直接覆盖正文。 |
| 文学/写作教师 | 展示文学技法、证据和过程性训练 | 能讲清“结论来自哪里”，而不是只展示一个分数。 |
| 数字人文学习者 | 上传文本并观察关系、结构、主题与语言数据 | 能从图、曲线、热力图和表格交叉验证文本观察。 |
| 评委/观众 | 在短时间看到技术深度 | 上传或打开一份作品后，得到多视图分析、具体诊断和下一步训练入口。 |

## 5. 信息架构与页面职责

1. **宣传首页**：展示品牌、叙事智能定位和入口动效。
2. **项目桌面 `/projects`**：创建、切换和进入项目；内置答辩案例不可删除。
3. **新建项目 `/projects/new`**：设置标题、类型、灵感和初始创作上下文。
4. **创作台 `/project/[id]/studio`**：灵感、人物、世界观、蓝图、正文、候选、版本和多轮方向对话。
5. **文学诊断 `/project/[id]/analysis`**：人物关系、情节结构、主题演变、语言风格、“为什么这样写”和证据详情。
6. **IP 实验场 `/project/[id]/ip-lab`**：视觉简报、分镜、生图参数和作品资产的实验性工作流。
7. **知识图谱 `/knowledge`**：经典知识库与“我的文本”双模式，支持文本提取、学术画布、指标、证据和表格。
8. **写作训练 `/training`**：六道练习、个人/课堂演示、过程反馈、版本差异和六维成长趋势。
9. **设置 `/settings`**：AI 状态、隐私说明、调用预算、导出和清除本地创作数据。

## 7. 关键用户流程

### 7.1 创作与多轮对话

1. 用户进入项目并编辑人物、世界观或蓝图。
2. 用户在创作台选择一个默认方向标签，或输入自己的问题。
3. AI 读取当前章节、正文、设定和上下文版本，先返回理解、建议、风险和追问。
4. 用户继续追问、补充条件或切换方向；对话只细化计划，不直接改正文。
5. 用户触发续写后，系统先跑上下文一致性检查，再把候选放入候选区。
6. 用户确认候选后才写入正文，并生成新的版本快照。

### 7.2 文学诊断与直接跳转

1. 用户从创作台点击“文学诊断”。
2. 系统带上 `projectId`、章节、`sourceKind` 和 `contextRevision`。
3. 分析结果分为人物、情节、主题、语言四域。
4. 每条具体建议包含位置、原文观察、影响、置信度和下一步实验；“此处铺垫不足”不能只有一句结论。
5. 用户点击“去专项训练”，系统只接受白名单练习 ID，异常 ID 安全回退。

### 7.3 上传文本与学术知识图谱

1. 用户上传 UTF-8 TXT/MD 或粘贴文本。
2. 客户端执行大小、字符数、空文件和编码检查；原文只在当前会话中使用。
3. `knowledge-extract` 返回节点、关系、证据和来源类型。
4. Cytoscape 以 Gephi/Palladio 风格绘制关系；用户可查看度数、中心性、关系类型、置信度和证据。
5. 表格视图作为精确查阅和 Canvas 不可用时的替代，不依赖装饰性连线。

### 7.4 写作训练

1. 用户选择练习，提交自己的答案。
2. AI 只评价答案中的证据、动作、感官、结构、语言和自主修订。
3. 反馈必须引用用户答案或核验来源，禁止返回一段可直接提交的替代作文。
4. 用户可以再次评价，系统通过 `previousAttemptId` 形成版本链并计算六维趋势。

## 8. AI、RAG 与数据边界

### 8.1 AI 任务协议

统一 `/api/ai` 路由支持：

`ideas`、`characters`、`world`、`blueprint`、`opening`、`prose`、`continue`、`rewrite`、`expand`、`condense`、`sensory`、`analysis`、`explain`、`mentor`、`visual-brief`、`storyboard`、`training`、`story-direction`、`consistency-check`、`analysis-v2`、`knowledge-extract`、`image-parameter-recommendation`、`training-feedback-v2`。

每个任务都有输入上限、预算、结构化输出约束和 validator。响应不能通过校验时，不写入作品状态，并返回明确的 Demo/失败提示。

### 8.2 RAG 边界

- 公共知识源按来源状态区分 `verified`、`pending`、`summary_only`。
- 公开/授权材料可以进入检索；受限原文不能因为“有向量”就自动开放。
- 检索支持关键词和向量路径；首版 embedding 公共检索默认关闭。
- 用户上传文本和当前项目正文是会话级材料，不进入公共知识库、StoryState 或 `ai_runs`。

### 8.3 零数据保留

- 用户项目、人物、世界观、训练答案和 AI 运行记录默认保存在当前浏览器 `localStorage`。
- 生图资产保存在 `IndexedDB/story-forge-assets`。
- 清除站点数据会清除用户作品；设置页提供清除入口。
- 产品页面只承诺“本站零数据保留”；第三方 AI 供应商是否短期保留请求取决于其服务条款。
- 公开文学知识使用随应用发布的本地目录。

## 9. 非功能需求与安全边界

| 类别 | 当前要求 | 验收口径 |

## 11. 答辩 Demo 黄金路径

1. 首页展示 Logo、品牌和“叙事智能”定位。
2. 进入“回响的草场”，展示内置案例稳定可用。
3. 在人物或世界观编辑器中修改一个设定，触发上下文一致性提示。
4. 进入文学诊断，打开关系图、情节节奏曲线和主题热力图。
5. 点击“此处铺垫不足”，打开原文证据、影响和专项训练入口。
6. 进入训练，提交一段自己的改写，展示六维反馈、证据逐字校验和版本差异。
7. 进入知识图谱，上传一份外部学生作文或当前作品，展示学术画布、指标、证据和表格视图。
8. 最后说明：无密钥或网络异常时，系统仍能用结构化本地回退完成 Demo；真实 AI 连接是可替换的服务端能力。

## 12. 路线与取舍

### P0：当前发布候选必须保持

- 创作台可编辑，候选必须确认后采纳。
- 人物/世界观/蓝图/章节上下文可追踪，一致性问题可提示。
- 文学分析、知识图谱和训练有证据链与失败关闭。
- 本地零数据保留、服务端密钥、限流和稳定回退。
- 答辩锁定模式关闭外部 AI、生图和云端同步。

### P1：下一轮增强

- 真实 DeepSeek、ModelScope 部署 smoke test、监控和余额告警。
- 逐条完成 verified/authorized 经典片段的来源与版权核验。
- 教师教研看板、匿名课堂样例和班级维度统计。
- 浏览器视觉回归和滚动性能指标自动化。
- 用户自愿分享人物卡、世界观摘要和首段的最小作品橱窗，默认署名、可撤回、不开放全文。

### P2/P3：当前明确不纳入

- 视频生成、完整多媒体资产包和社区/IP 经济体系。
- Vue 页面迁移。当前产品是 Next.js/React，本轮使用 GSAP/ScrollTrigger，避免双框架运行时。
- 机构版权权限体系和大规模知识库运营。

## 13. 评委质疑与标准回答

**“这和普通 AI 写作有什么区别？”**  
普通工具以生成文字为中心；故事熔炉以中文文学教育、上下文一致性、文本证据、可视化分析和过程性训练为中心。

**“知识源数量有限，能叫知识图谱吗？”**  
当前 Demo 验证的是可扩展 Schema、来源状态、证据闭环和分析工作流，不把样例规模包装成完整数据库；后续可通过高校授权目录和公开元数据扩展。

**“AI 会不会替学生写作业？”**  
训练 v2 禁止 replacement/prose，反馈只能引用用户回答或核验来源；课堂模式不提交、不写个人训练历史。

**“为什么不自己训练大模型？”**  
模型层可替换，产品壁垒在文学任务 Prompt、RAG Schema、证据协议、上下文工程和教学工作流，不重复建设基础模型。

**“能否直接导出课程作业 PDF？”**  
当前稳定导出 Markdown/TXT；PDF 排版、教师看板和班级统计属于后续版本，答辩不虚构已完成能力。
