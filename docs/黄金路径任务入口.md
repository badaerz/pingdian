# 黄金路径的 22 个 AI 任务入口

2026-11-20 源码审计。以 `src/lib/ai/tasks.ts` 的 `AI_TASKS` 为分母，追踪 App Router 页面实际挂载的组件。以下“入口”表示有可达请求路径，不代表已经使用供应商密钥逐项实测。

| 任务 | 页面、触发条件 | 无有效配置时可观察的结果 |
|---|---|---|
| ideas | 新建项目，第 1 步生成故事方向 | 演示方向候选，可手动采用 |
| characters | 新建项目，第 2 步生成人物与世界 | 演示人物设定，与世界设定一并确认 |
| world | 同上，按钮并发发起第二个请求 | 演示世界设定，界面按人物和世界分别标注演示来源 |
| blueprint | 新建项目，第 3 步生成故事蓝图 | 演示蓝图，确认后进入表单 |
| opening | 新建项目，第 4 步生成首段候选 | 演示候选，采用后仍可编辑 |
| prose | 创作台候选栏，改写整段 | 带演示标记的候选 |
| continue | 创作台方向讨论，生成续写候选 | 带演示标记的续写候选 |
| rewrite | 创作台选中正文，改写 | 演示改写候选 |
| expand | 创作台选中正文，扩写 | 演示扩写候选 |
| condense | 创作台选中正文，精简 | 演示精简候选 |
| sensory | 创作台选中正文，感官细节 | 演示描写候选 |
| analysis | 旧任务，仅 API 注册 | 旧分析结构的演示响应，当前分析页调用 analysis-v2 |
| mentor | 创作台选区导师，或分析页询问导师 | 导师解释带演示状态 |
| visual-brief | 项目 IP 实验场，生成视觉简报 | 候选上有演示标记，可确认 |
| storyboard | IP 实验场，保存主视觉后生成六镜头分镜 | 六镜头演示候选带独立来源徽标 |
| training | 旧任务，仅 API 注册 | 旧反馈结构的演示响应，当前训练页调用 training-feedback-v2 |
| story-direction | 创作台输入方向或选择标签，发送并继续讨论 | 助手消息携带演示标记 |
| consistency-check | 当前章节出现待选候选，自动检查，失败可重试 | 报告单独显示演示检查，候选与报告可来自不同模式 |
| analysis-v2 | 分析页选择作品来源或导入文本后分析 | 演示诊断；作品来源保存带模式快照，导入来源仅当前会话 |
| knowledge-extract | 知识页，我的文本输入或导入 TXT/MD 后提取 | 结果标为演示；仅当前会话 |
| image-parameter-recommendation | IP 实验场，能力列表就绪后使用 AI 推荐参数 | 参数草案标注演示推荐，手动应用 |
| training-feedback-v2 | 训练页个人练习，输入答案后提交 | 演示反馈；可写入本机历史，课堂展示模式禁用提交 |

入口代码在 `src/components/projects/new-project-form.tsx`、`studio/candidate-panel.tsx`、`studio/story-direction-chat.tsx`、`analysis/analysis-workspace.tsx`、`knowledge/knowledge-workspace.tsx`、`training/training-workspace.tsx` 和 `ip-lab/ip-lab-workspace.tsx`（后六项均相对于 `src/components/`）。创作设定组件 `studio/setup-panel.tsx` 的四类任务另有组件测试，当前页面没有挂载该组件。IP 实验场路由同时挂载愿景介绍与操作区。

## 模式与失败边界

服务端在答辩锁定时忽略用户密钥并清空服务端密钥。未锁定时优先使用合法用户密钥，未提供用户密钥时使用服务端配置。因此仅清空浏览器密钥不足以验证离线模式。合法请求且双方均无密钥时，全部任务在检索和模型调用前直接返回 `mode: "demo"` 和原因。各任务回退形状见 `src/lib/ai/fixtures.ts` 的 `fixtureForTask`。模型请求失败或模型响应校验失败也可返回 demo，此时页面文案“未调用模型”可能与实际请求经历不符。无效密钥格式返回 400，限流返回 429，不能一概作为 demo 处理。见 `src/app/api/ai/route.ts`、`src/lib/ai/tasks.ts` 的 `runAiTask` 和 `tests/unit/ai-tasks.test.ts`。

## 可复核的异步用例（初次审计）

| 用例 | 初次审计的代码行为 | 修复后预期与复核位置 |
|---|---|---|
| 训练提交后、响应返回前编辑答案，再尝试提交 | 答案版本变化导致成功与错误处理均提前返回。finally 仅清空控制器，状态仍为 loading，提交按钮持续禁用 | 编辑立即恢复可提交状态，旧请求失效。见 training-flow.test.tsx |
| 在 React StrictMode 下首次打开训练页并提交 | Effect 的清理将 mountedRef 置为 false，重放 setup 时没有恢复，submit 入口提前返回 | 首次提交仍能发出请求。见 training-flow.test.tsx |
| 向导先发起方向生成，再进入第 2 步才返回响应 | 步骤切换清空候选，但先前请求仍可 setPending。候选渲染只检查 kind，旧方向可能出现在人物与世界步骤 | 步骤切换后旧请求不回填内容。见 new-project-wizard.test.tsx |
| 人物请求返回 demo、世界请求返回带 warning 的 live，且 live 最后返回 | 两次 call 分别写入同一 warning，后一条可覆盖前一条来源提示 | 同时显示人物的演示来源和世界请求的警告。见 new-project-wizard.test.tsx |
| 先生成真实正文候选，再令一致性检查降级 | 候选图标显示候选生成来源，报告状态行依据风险显示；仅凭候选来源无法判断本次检查是否实时 | 报告按响应顶层模式标注，候选保留自己的标注。见 candidate-recovery-consistency.test.tsx |

已有回归入口包括 `tests/components/candidate-panel-chapter-scope.test.tsx`、`candidate-panel-unmount.test.tsx`、`training-flow.test.tsx`、`new-project-wizard.test.tsx`、`ip-lab-flow.test.tsx` 和 `tests/unit/authenticity-guard.test.ts`。静态守卫验证源码读取 mode，无法证明运行时的徽标归属或异步回包顺序。
