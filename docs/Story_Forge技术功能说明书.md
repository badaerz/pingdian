# Story Forge 故事熔炉

**面向读者**：文科生、产品经理、自学开发者、比赛答辩成员  
**对应版本**：`v0.1.0-rc.1`  / 提交 `af14bc7`  
**更新时间**：2026-08-22

## 1. 先用一句话理解产品

故事熔炉可以理解为“文学创作编辑器 + 文本分析实验室 + 写作训练教室”。

用户先在创作台建立故事，再让 AI 帮忙讨论和提出候选；用户确认后才采用。作品还可以被分析成关系图、情节曲线、主题热力图和训练建议。系统的重点不是“替用户写完”，而是让创作过程有依据、能回看、能发现矛盾、能继续学习。

## 2. 用户能看到的主要模块

### 2.1 首页与项目桌面

首页展示 Story Forge 品牌、Logo、叙事智能定位和页面滚动动效。项目桌面负责项目入口、案例项目和本地状态。

内置答辩案例是稳定素材，不能被删除；用户新建的项目则属于自己的本地创作空间。

### 2.2 创作台

创作台是主工作区，包含：

- **灵感**：让 AI 提供几个不同方向的故事起点。
- **人物**：编辑人物的身份、欲望、恐惧、缺陷、关系和弧光。
- **世界观**：编辑地点、时代、规则、限制和氛围。
- **蓝图**：用章节和情节点组织故事推进。
- **正文**：使用 Tiptap 编辑器写作，支持版本抽屉和 Markdown/TXT 导出。
- **候选面板**：AI 结果先进入候选区，用户确认、拒绝或重试。
- **方向对话**：用户先和 AI 讨论下一步，而不是被动接受 AI 直接生成的候选。

每轮方向对话会提供默认标签：

`跌宕起伏`、`轻松日常`、`推进冲突`、`深化人物关系`、`埋设悬念`、`强化情感`。

这些标签只是快捷入口，用户仍可以自己输入问题。对话返回的是“我理解了什么、建议怎么走、有什么风险、还需要问什么”，不会直接覆盖正文。

### 2.3 上下文一致性

续写前，系统把当前项目的关键事实整理成上下文快照：

- 当前章节和正文末尾动作
- 人物的欲望、恐惧、性格和关系
- 世界观规则、地点和时代限制
- 蓝图中的章节作用和已发生事实
- 当前上下文版本号

AI 续写候选生成后还会执行一致性检查。例如：前文规定人物害怕水，候选却让他主动跳入深水；或者世界观规定某地没有电，候选却出现手机充电。系统会把这类问题标成风险，给出可核验的候选句和原有设定，并在高风险时阻止直接采纳。

这体现的是“生成之后检查”，而不是只看文字是否通顺。

### 2.4 文学诊断与“为什么这样写”

文学诊断包含四类内容：

1. **人物**：人物目标、行动、关系变化和角色弧光。
2. **情节**：转折点、铺垫、回收、冲突强度和节奏变化。
3. **主题**：主题或意象在章节中的出现和演变。
4. **语言风格**：句长、对话比例、感官密度、修辞、叙事距离和节奏。

“为什么这样写”不是泛泛点评。一个合格的诊断需要说明：

- 发生在文本什么位置
- 引用了哪段原文观察
- 使用了什么文学技法或结构判断
- 对读者效果和情节推进有什么影响
- 结论的置信度如何
- 下一步可以做什么小实验或专项训练

例如“此处铺垫不足”必须能点击回原文，而不是只显示一个红色警告。

### 2.5 学术级知识图谱

用户可以上传 TXT/MD 文本或粘贴当前项目文本。系统分析后生成：

- 人物、事件、地点、主题、意象、技法等节点
- 节点之间的关系边
- 关系类型和置信度
- 节点度数、中心性等指标
- 原文证据抽屉
- 可检索的表格视图

画布使用 Cytoscape，布局参考 Gephi、Palladio 等数字人文工具：力导向展示网络结构，分层布局展示不同类型的层级，同心布局展示核心与外围关系。表格视图不是附属装饰，而是精确查阅和 Canvas 不可用时的替代。

系统还区分两种文本：

- **叙事文本**：可以分析人物、事件、地点和情节关系。
- **论述文本**：更关注论点、证据单元和推理步骤，不强行套用人物关系模型。

### 2.6 写作训练

首版有六道练习，覆盖：

- Show Don't Tell
- 人物动作
- 对话潜台词
- 冷峻白描
- 场景描写
- 铺垫和回收

训练反馈只回答“你的答案哪里有效、哪里有问题、下一步如何实验”。它不会返回一段可以直接交作业的替代作文。

系统固定使用六个成长维度：证据具体性、动作设计、感官细节、结构节律、语言控制、自主修订。再次评价会记录前后版本差异，形成同一道题的版本链。

### 2.7 IP 实验场和生图参数

IP 实验场用于将故事设定整理为视觉简报、分镜和生图参数。生图参数编辑区包括：

- 正向提示词
- 负向提示词
- 模型选择
- 尺寸
- 步数
- CFG
- seed
- 其他由供应商能力白名单允许的参数

“AI 推荐参数”任务会读取当前人物、场景、媒介、色彩和正文证据，返回参数、理由和置信度。无 ModelScope 密钥时返回稳定的本地结构化回退；有密钥时才进入真实供应商流程。

当前产品对 ModelScope 采用“模型 + prompt”为稳定基础契约，其他参数是否真正生效取决于供应商能力列表，不能把前端输入框等同于供应商一定支持。

## 3. 技术栈，用不懂代码的方式解释

| 技术 | 在项目中的作用 | 可以怎么理解 |
| --- | --- | --- |
| Next.js 16 | 网站框架、页面和服务端 API | 负责把网页和后端接口放在同一个项目里。 |
| React 19 | 页面组件和交互状态 | 把“编辑器、按钮、面板”拆成可复用积木。 |
| TypeScript | 类型检查 | 提前发现“把章节当成人物”这类结构错误。 |
| Tiptap | 正文编辑器 | 提供真正可编辑的富文本区域。 |
| Cytoscape | 学术知识图谱 | 负责节点、边、布局、缩放和选中。 |
| Recharts | 曲线和趋势图 | 绘制情节、情绪和训练成长趋势。 |
| GSAP + ScrollTrigger | 首页和页面滚动动效 | 让内容随滚动有节奏地出现；不负责业务数据。 |
| Radix UI | 对话框、标签页、弹层等基础交互 | 提供可访问的 UI 行为。 |
| localStorage | 项目、正文和训练记录 | 浏览器里的小型本地数据库。 |
| IndexedDB | 生图资产 | 适合保存较大的图片文件。 |
| Supabase + pgvector | 可选的公共文学知识库 | 保存公开/授权知识和向量检索，不是首版用户作品仓库。 |
| DeepSeek API | 可替换的文本模型服务 | 负责理解、生成、分析和反馈。 |
| ModelScope API-Inference | 可选的图像模型服务 | 负责异步生成图片。 |
| Docker + Nginx | 生产部署 | Docker 运行应用，Nginx 负责 HTTPS、域名和限流。 |

项目当前是 Next.js/React，不是 Vue 项目。GSAP 和 ScrollTrigger 已经承担网页动画，不再为了动画引入第二套 Vue 运行时，避免打包体积和状态边界变复杂。

## 4. 系统如何处理一次 AI 请求

可以把一次请求理解成七步：

```text
用户操作
  ↓
页面组件收集当前项目和输入
  ↓
构造上下文快照
  ↓
/api/ai 判断任务、预算和输入长度
  ↓
RAG 提供可用的公开/授权证据
  ↓
DeepSeek 或本地 Demo 回退
  ↓
结构化 validator 检查结果
  ↓
候选、分析、反馈或错误状态返回页面
```

### 4.1 任务层

代码把 AI 请求分成明确任务，例如 `story-direction`、`consistency-check`、`analysis-v2`、`knowledge-extract`、`image-parameter-recommendation` 和 `training-feedback-v2`。

这样做的好处是：每个任务有自己的输入、输出和验证规则，不会让一个“万能 Prompt”同时负责写作、分析、训练和生图。

### 4.2 上下文层

上下文层把项目拆成模型能理解的事实包，包括人物、世界观、蓝图、章节和正文窗口。每次保存都会推进上下文版本；旧请求回来时，如果版本已经变化，系统不会让旧结果覆盖新状态。

### 4.3 验证层

验证层检查：

- JSON 结构是否正确
- 必填字段是否存在
- 证据是否真实来自本次文本
- 节点和边的 ID 是否能互相对应
- 训练反馈是否出现了禁止的代写正文
- 生图模型是否来自当前能力白名单

因此，“模型输出了一段看起来很聪明的话”还不等于“产品接受了这段话”。

## 5. 数据如何保存与删除

### 5.1 用户创作数据

默认保存位置是用户当前浏览器：

- 项目、章节、人物、世界观和训练记录：`localStorage`
- 生图资产：`IndexedDB/story-forge-assets`

服务器不会因为用户新建项目就自动建立用户数据库记录。设置页的清除入口会删除本地创作数据；用户也可以在浏览器设置中清除该站点的网站存储。

### 5.2 公共知识数据

随应用发布的练习、演示项目和公开/授权知识种子属于产品素材，不属于个人用户作品。Supabase 只在启用公共知识检索时承载 `kb_works`、`kb_chunks` 等知识数据。

### 5.3 外部 AI 的边界

产品承诺的是“本站零数据保留”。文本一旦发送到 DeepSeek 或图片一旦发送到 ModelScope，第三方如何按其服务条款处理，需要看供应商规则；答辩锁定模式会关闭这些外部请求。

## 6. 主要 API 和服务器职责

| 路由 | 用途 | 特点 |
| --- | --- | --- |
| `/api/ai` | 统一文本 AI 任务 | 预算、超时、结构校验、Demo 回退。 |
| `/api/generate` | 兼容旧的文本生成入口 | 与统一预算共享，保持旧页面可用。 |
| `/api/assets/capabilities` | 查询可用生图模型和参数能力 | 只返回白名单能力。 |
| `/api/assets/generate` | 创建图片生成任务 | 服务端调用 ModelScope，不暴露 token。 |
| `/api/assets/status` | 查询异步生图状态 | 有频率限制和超时。 |
| `/api/assets/download` | 下载确认后的图片 | 严格检查 HTTPS、主机和后缀。 |
| `/api/knowledge/search` | 查询公开知识 | 失败时回退本地目录，不接收用户作品持久化。 |
| `/api/health` | 健康检查 | 只返回状态、服务名和版本，不泄露模型或密钥。 |

AI 请求默认限制为单客户端每分钟 10 次、全局每日 200 次；Nginx 还有第二层按路由限流。

## 8. 安全与可维护性

### 8.1 密钥安全

DeepSeek、ModelScope 和 Supabase service role key 不进入浏览器，不写进 Docker 镜像，也不提交 Git。`.env.production.example` 只有空值模板，真正的服务器环境文件需要单独保存并设置为 `chmod 600`。

### 8.2 失败处理

- 没有密钥：返回标记清楚的本地 Demo 结果。
- API 超时：显示状态和重试入口，不让页面崩溃。
- 旧请求晚回来：通过 AbortController、序列令牌和上下文版本拒绝覆盖新结果。
- 知识图谱文本非法：拒绝新文本并清空旧图谱，避免用户误以为旧结果来自新文件。
- 图谱 Canvas 不可用：保留列表和表格视图。

### 8.3 可维护边界

AI 任务、结构校验、RAG、项目存储和 UI 视觉 token 分开。替换 DeepSeek 或 ModelScope 时，优先替换服务端 provider 适配，不需要重写所有页面。

### 9.2 生产构建

```powershell

```

### 9.3 服务端 AI 配置

在 `.env.local` 中填写服务端变量，不要使用 `NEXT_PUBLIC_` 暴露密钥：

```env
DEEPSEEK_API_KEY=服务端密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-chat
MODELSCOPE_API_TOKEN=服务端令牌
MODELSCOPE_API_BASE_URL=https://api-inference.modelscope.cn
MODELSCOPE_IMAGE_MODEL=Qwen/Qwen-Image
SUPABASE_URL=可选
SUPABASE_ANON_KEY=可选
```

没有密钥也可以跑完整本地 Demo，但结果是结构化回退，不代表真实供应商已经联通。

### 9.4 锁定答辩模式

锁定模式必须在构建时设置：

```powershell
$env:NEXT_PUBLIC_DEMO_LOCKED="true"
npm.cmd run build
npm.cmd run start
```

此模式关闭外部 AI、生图和公开向量检索，内置答辩案例只读，演示不依赖网络模型响应。普通用户仍可以创建用户项目进行交互。

## 11. 比赛答辩的技术表达

可以用这段话解释技术壁垒：

> 故事熔炉没有重复训练一个基础大模型，而是把文学任务工程化。应用层负责创作、诊断、图谱和训练；任务层负责人物一致性、叙事分析和技法反馈 Prompt；知识层用可扩展的作品-人物-主题-时代-技法 Schema 加来源状态和证据；模型层可以替换 DeepSeek、ModelScope 等供应商。这样，产品价值不押在单一模型，而押在文学知识、证据协议、上下文工程和教学工作流。

### 评委追问速答

**为什么不是普通思维导图？**  
因为图谱节点和边都有类型、置信度、度数/中心性和原文证据，并且有表格视图；画布是分析结果的入口，不是装饰。

**怎样保证 AI 不把人物写崩？**  
续写前读取人物、世界观、蓝图和章节快照；生成后再做一致性检查。高风险矛盾不会直接覆盖正文，用户必须看到并处理。

**怎么防止 AI 代写作业？**  
训练反馈只能评价用户回答，禁止 replacement prose；课堂模式不提交个人训练历史。AI 生成文本必须进入候选区，用户确认后才改变正文。

**为什么要本地保存？**  
个人网站和比赛 Demo 先把数据边界做小：作品归用户浏览器，清除网站数据即可管理；服务端只承载可选的公共知识库和模型代理。

## 12. 词汇表

| 词 | 通俗解释 |
| --- | --- |
| API | 网站与外部服务说话的接口。 |
| Prompt | 给 AI 的任务说明，不只是“请写一段话”。 |
| Validator | 检查 AI 返回格式、证据和安全边界的程序。 |
| RAG | 先查找相关知识，再把有来源的材料交给 AI 参考。 |
| Context Revision | 当前作品上下文的版本号，用来防止旧结果覆盖新内容。 |
| Evidence | 能回到原文或用户回答的证据。 |
| Local-first | 先在用户设备保存，服务器不是默认数据库。 |
| Demo fallback | 没有外部 API 时使用的确定性结构化演示结果。 |
| Gephi/Palladio 风格 | 强调网络结构、指标、筛选和来源，而不是普通节点树。 |
