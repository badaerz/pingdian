## 6. 已知问题（需要你裁定）

### 6.1 ref 命名不统一，掩盖了同作品条数（重要）

R5 只比较 `source.ref` 字符串，而历史条目的 ref 是知识库编号（`KB_002`、`KB_005`），新条目是篇名（`水滸傳·第003回`、`聊齋志異·葉生`）。结果是：

- **水滸傳实际 3 条**：GC_004（KB_002）、GC_019（KB_002）、GC_005（水滸傳·第003回）
- **聊齋志異实际 4 条**：GC_007（KB_005 促织）、GC_023（KB_005 促织）、GC_002（葉生）、GC_008（畫皮）

checker 全部放行，因为字符串不同。两个修法：

1. **统一 ref 为作品名**（`水滸傳`、`聊齋志異`），然后必须各砍掉超出的条目（水滸去 1、聊齋去 2），golden 从 46 降到 43，缺陷样本仍 3/3。
2. **声明 ref 粒度 = 篇目/回目**（`聊齋志異·葉生` 与 `·畫皮` 视为两篇），则现状合法，但要在 schema 文档里写清这条口径。

我倾向 1（口径更硬），但这会减少样本量，且要重挑两条聊齋的替换源，所以先问你。

### 6.2 质量分档只有"全 defect"才算缺陷样本

GC_032/033（1 defect + 2 positive）被 checker 判为 `mixed`，不计入"缺陷样本"配额。GC_046 同样是 mixed。如果你希望"含缺陷即可计入"，需要改 checker 第 100–105 行的分档逻辑——我没动检查器。

### 6.3 文言比例上升

换源后文言/古白话占 9 条（001、002、005、006、008、031、034、035、040）。这对"现代写作教练"的产品叙事略有张力，但对判据的可判定性是加分（名物、数目、动作链更清楚）。如果你在意，可以下一批把 002 或 008 换成现代公版文本。

### 6.5 `forbiddenClaims` 的判据编号是规则映射，不是逐条判定

FC 的 `criteriaIds` 由生成器按"该 case 的主维度 + 关键词"填，不是我对每条反例单独判定。审计结果：46 条里有 **7 条的 FC 判据集合与 EF 完全相同**（说明该条反例的"假借判据"没有细化）。不影响 checker 通过，但如果你要拿 FC 做"模型假借了哪条判据"的归因统计，这 7 条需要人工再指一次。

### 6.4 没有"公认写得差的公版文本"

任务书允许用"公版作品公认败笔段"，但这类"公认"很难举证（说某段是败笔需要文献支撑，否则就是我的主观判断）。所以三条缺陷样本全部走"自造 AI 套路文"这条路——它不涉版权、可控、且正好对着产品要防的东西（AI 生成的空转文本）。
