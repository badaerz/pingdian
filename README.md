# 评点 PINGDIAN

把批注钉在原文上的中文文学诊断工具。

**怎么用：** 打开首页，把一段中文贴进输入框，点「开始诊断」，十几秒后看右侧批注；点任意一条批注，左边原文会定位到对应那一句。

---

## 下载与运行

**方式一：直接下载（推荐）**

1. 打开 [Releases](https://github.com/badaerz/pingdian/releases) → 下载 `Source code (zip)`
2. 解压，进入文件夹
3. 装 [Node.js](https://nodejs.org) 20 或以上
4. 双击 `一键启动-Windows.bat`；macOS / Linux 在终端执行 `bash 一键启动-macOS-Linux.sh`
5. 浏览器自动打开 `http://localhost:3000`

首次运行会自动装依赖并构建，约 3–5 分钟，之后每次启动几秒。

**方式二：Docker**

```bash
docker compose up --build
# 打开 http://localhost:3000
```

**密钥**：不填也能完整跑。所有 AI 功能走标注清楚的「演」演示态，内容取自真实跑过的分析结果。想用真实调用，打开站点 → 设置 → 自带 AI 密钥，填一个 DeepSeek 的 key（以 `sk-` 开头）。密钥只存在浏览器里，服务端不存库、不记日志。

## 一、产品定位

### 是什么

一个网页工具。用户贴一段中文，工具给出文学诊断批注，每条批注绑定原文里的某一句话。

它不做写作辅助。不生成正文，不做章节管理，不做大纲规划。产品只做一件事：**指出一段文字哪里有问题，并证明这个判断指得出位置。**

### 解决了什么问题

用大模型点评一篇小说，今天任何人都能在十分钟内做出一个原型。真正投入使用时有两个问题：

**结论空泛。**「这里节奏拖沓」说不出哪一段，「人物略显单薄」换成另一篇小说同样成立。用户看完不知道要改哪里。

**伪造引用。** 模型引用一句原文来支撑判断，而那句话在原文里并不存在。用户看不出来，所以这一条更危险。

第一个问题是质量问题，第二个是信任问题。信任问题不解决，产品在真实使用场景里无法成立。

### 怎么解决的

把「引用」从输出的附属品改成准入条件。

模型返回每条诊断时必须附一句原文。校验器拿这句话去用户原文里做字符级比对：定位不到，该条诊断直接作废，不进入界面；定位到，用原文那一段的真实字符覆盖模型写的引文，做标点规范化后回写。

界面只渲染通过校验的内容。左下角固定显示 `本轮丢弃 N 条`，展开可看到被丢弃的条目和原因：引文逐字不符、无法定位到原文、判据未注入。

判断依据来自一套 18 条判据的知识库，六个维度各 3 条：

| 维度 | 看什么 |
|---|---|
| 具体性与感官 | 抽象判断有没有换成可指认的细节 |
| 意象复现 | 反复出现的物件有没有承载含义 |
| 结构组织 | 段落功能和转折 |
| 连贯衔接 | 句与句的衔接 |
| 信息密度与节奏 | 单位篇幅的新信息量 |
| 视角一致性 | 叙述者有没有越界 |

每条判据带有可判定描述、正例、反例、常见误报、不适用条件等字段。其中 `C1`、`D2` 两条阈值未定，目前只采集数值、不下结论。

## 二、功能描述

**诊断** — 贴一段中文，得到六个维度的批注。每条批注带引用原文、依据的判据编号、置信度。点批注，原文对应句高亮，其余压暗。界面提供可解释面板，分输入、检索、任务、校验四段展示本次分析过程。

**训练** — 六道写作练习。提交后给结构化反馈：做到了什么、还缺什么、下一步做什么。反馈中引用的句子必须逐字来自用户输入。

**知识图谱** — 从文本里提取人物、意象、关系节点，每个节点带原文证据。悬停节点，原文对应句亮起。

**创作台** — 续写、改写、润色。结果先进入候选面板，用户点「采纳」才写入正文。

**项目桌面** — 作品列表与本地存储管理。支持导出为 JSON、导入、清除本地数据。

**IP 实验场** — 视觉简报、分镜、主视觉候选的概念流程。配置 ModelScope token 时调用真实生图，未配置时展示演示态。

**设置** — 自带密钥、正文字号五档、导出、清除数据。

首页有一段杜甫《登高》的演示，内容来自一次真实分析。

## 三、效果报告

| 指标 | 数值 | 口径 |
|---|---|---|
| 证据可溯源率 | **100%** | 三轮实测，215 / 222 / 242 条诊断逐字可查 |
| 幻觉率 | **0%** | 不存在原文中定位不到的引用 |
| 结论准确率 | **20.0%** | 46 篇样本 / 135 条预期发现，三轮中位数（16.00 / 22.55 / 20.00） |
| 整包回退率 | **4.3%** | 单条丢弃规则启用后，原为 19.6% |
| 首屏 LCP | **约 1.1 秒** | 4× CPU 降速 + 1.6 Mbps 限速下实测 |
| 自动化测试 | 446 用例 / 66 文件 | 另有 Playwright 20 用例 × 三档屏幕 |
| AI 任务 | 22 个 | 均完成过至少一次真实调用 |

结论准确率的读数需要限定条件：评测口径要求模型引文落在专家标注的同一句上，且给出同一维度的判断，命中标准偏严。该指标用于回归检测（下降超过 3 个点视为回归），不作为对外质量承诺。

漏报归因：108 条漏报中，71% 是模型未走到标注位置，29% 是走到了但未给出对应结论，判据未注入导致的为 0 条。

评测方法与完整数据见 `evals/reports/`。

## 四、项目现状

**已完成**：诊断主链路、6 个辅助功能、22 个 AI 任务、46 篇审定样本的评测体系、Docker 与本地一键启动、开源发布（MIT）。

**已知问题**：

| 问题 | 说明 |
|---|---|
| 结论准确率 20% | 主要瓶颈是判据覆盖面，模型经常未走到应检查的位置 |
| 标注仅一人 | 46 篇样本由 AI 起草、一人审定，无法计算标注者一致性 |
| 无真实用户数据 | 上述指标均为自测 |
| IP 实验场生图 | 依赖第三方 token，无 token 时仅演示态 |

**下一步**：扩充判据覆盖面、引入第二标注者计算一致性、收集外部用户反馈。
